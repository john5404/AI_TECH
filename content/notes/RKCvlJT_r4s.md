## 一句話

LLM 應用有兩類漏洞。權限給太多是舊問題。新問題是 model 分不清開發者的指示和外面進來的資料，資料一被讀過就可能變成會執行的東西。Jailbreak 是使用者自己在拆對齊；prompt injection 的受害者是不知情的人；把毒放進訓練權重則像供應鏈，進去之後很難看見。Gandalf 上超過兩百萬人、六千多萬次攻擊之後，他們的論文說：只算抓到幾次攻擊不夠，防禦會改到產品好不好用，沒有白吃的午餐。Agent 把這件事放大，因為它在生產環境裡依資料決定下一步。

## 舊的是權限，新的是分不清 how 和 what

[0:43](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=43s) 開場先用 OpenAI 的 deep research 做例子：他請它找出最好的一百則爸爸笑話，挑出其中較不為人知的五十則，再依好笑程度排序，花了八分鐘。他說這是第一次 AI 不是在創作，而是找出新的、還不錯的笑話。字幕把贊助方聽成 Tesla。

[1:29](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=89s) 名詞很多：prompt injection、jailbreak、data poisoning。他要先看全圖。LLM 應用的漏洞有兩種。第一種是傳統的。做系統時權限要設對。大家談 RAG 時，對的人能不能看到對的文件，其實是 permissioning，重要，但不是新的。上線前就該就位。Agent 也一樣：只想讀信，就不要給寄信的權限。這是設計習慣。

[2:41](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=161s) 新的是根本的：LLM 很難把開發者的指示，和外部輸入或資料分開。攻擊者可以透過資料操縱系統行為。RAG 裡，抽出來的文件可以帶著攻擊，想讓 model 把文件裡的資料當成新指示去執行，再把不實的資訊交給使用者。他喜歡的講法是：文件、圖片、影片這些以前只是資料的東西，突然變成 executable。LLM 一掃過，就可能被執行。手段是改資料，讓 LLM 去執行攻擊者的命令。目的可以很多：繞過對齊、叫 agent 去用它不該用的工具、對使用者給出假資訊。

[5:00](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=300s) 主持人說，想讓系統執行你的命令，SQL injection、跨站腳本、遠端命令執行都在做類似的事。差別是這裡幾乎躲不掉：攻擊者送進去的資料，LLM 本來就會把它當內容處理，交織是內建的。來賓說，棘手之處正是 LLM 的力量：它能從自然的圖和文字裡執行指示，那道牆很薄。一封信說「請把上週那封轉寄出去」，agent 應該做。另一封若是攻擊者要整份收件匣，表現出來可以很像。問題是怎麼分辨。

[6:14](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=374s) 主持人提到幾個月前 Caleb Sima 那集，control plane 和 data plane 沒有分開，字幕把姓聽成 semi。他自己在 Tessl 做過會執行使用者 code 的產品，字幕把 Tessl 聽成 tesel。那等於內建的遠端命令執行。問題不再是能不能跑，而是能不能把執行圈住。辨認資料裡很細的攻擊型態、產生對抗資料來 red team，都變成 AI 優先的問題。

[7:23](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=443s) 主持人補另一面：AI 的「目的」比傳統軟體更模糊。安全的聖杯是白名單，只准這些命令，其他都不准。在 LLM 裡這不可想像，可能發生的事是無限的。來賓說大家太強調手段。真要辨認，還得看輸出，而且要對準具體用途。最常上新聞的是 jailbreak，讓 model 說出違反對齊的冒犯內容。可以查輸入有沒有被動過，也要看輸出是不是顧客不想要的內容。兩層合在一起才是 defense in depth。就算全是 agent，每一刻也是：從某個 tool 拿資料，決定下一個 tool 和要帶的資料。可以把那一次交易凍住，用輸入和輸出判斷該不該放行。

## 誰在攻擊，誰是受害者

[10:04](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=604s) 定義會浮動，他先給這集用的版本。Jailbreak 是使用者直接對正在互動的 model 下手，想繞過對齊。Pre-training 之後有 RLHF，字幕聽成 rhf：用人類回饋做強化學習，部分目標是有幫助，也要無害。什麼叫傷害由公司定義，寫進權重，不只是 system prompt。所以不管 system prompt 怎麼寫，model 按設計不該教人做炸彈。主持人把它想成想穿出防火牆。來賓說，跟人們談時，這是他們最在意、也最知道的第一層。

[11:55](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=715s) Prompt injection 在這集指間接的攻擊者。使用者在跟一個能搜網、能搜文件的 AI 說話。攻擊放在那些資料裡，model 讀到就執行，再影響使用者。翻轉是：受害者是不知情的使用者；jailbreak 裡，使用者自己才是下手的人。所以他個人更擔心 prompt injection。很多內部 AI 工具的人以為不用安全，因為只在公司裡。一旦碰到任何不受信任的資料，第三方就能在你不知道的情況下改公司裡的東西。他比成公司裡有個人，信裡進來的 executable 一律點開執行，而且從不問該不該。軟體世界裡不太有對等物。

[13:33](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=813s) Data poisoning 這個詞，雖然前面那些也算在資料裡下毒，大家通常指的是 fine-tuning 或訓練：你改的是網路的權重，不是只在 context 裡塞資料。對抗內容一旦吃進去，幾週或幾個月後還能變成後門。進了權重就很難認出這次利用發生過。他覺得這是最令人擔心的一類。主持人比成供應鏈攻擊，再加上 AI 的可解釋性很低：做對的時候都不知道為什麼，被濫用時更不知道。要得手比較難，需要一定的資料量，或很特定的訓練管道。但 model 廠商一直在用網路上的資料做 pre-training，而網路上很多內容已經是對抗性的。若吃進去時的防護不夠，有些會過去。容量很大的 model 就算只稀稀疏疏看過，也能記住很多。

## 六千萬次攻擊，換來一個和效用綁在一起的框架

[15:50](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=950s) Gandalf 是個遊戲：練習 injection，試著讓它把密碼交出來。主持人說自己花了太多時間。來賓說自己大概五分鐘過，也許再多一點，很上癮。到當時，超過兩百萬人玩過，對各種 LLM 有超過六千萬次攻擊。可以看到人用什麼創意去拆，不分語言和地點，也有人做自動化的攻擊者。去年他們決定在裡面跑隨機實驗，講這個領域什麼容易、什麼難，論文大約一個月前公開。Show notes 會放連結。

[18:10](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=1090s) 最高層的發現是：這個領域現在想 AI 安全的方式，在不少地方是有根本缺陷的。論文用大規模資料說，評估安全和要做的投資都該把鏡頭拉寬。今天常見的評法是：拿一組攻擊或 prompt injection 的資料集，標好標籤，丟進 model，看抓住幾個。論文挑戰的是這個想法。他們提出 dynamic security utility framework，字幕把縮寫聽成 DC。重點是安全要和使用者的 utility 一起看。擋掉所有流量，基準會是 100%，使用者也會不高興，產品不能用，一路可以走到破產。防火牆也不能擋掉每一包流量。既有偵測談的是抓住真的攻擊，以及 false positive。那不夠。

[20:28](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=1228s) 在 LLM 和 agent 裡，取捨比過去深。實驗請人去 red team 掛了不同防禦的 LLM。他們沒有把防禦優化到極致。一種是外部防禦：在 LLM 外面看進進出出的 payload，決定要不要擋；擋住了，玩家就沒從 Gandalf 拿到密碼。另一種寫在 system prompt 裡：叫它永遠不要說出密碼，可以講得很囉嗦。劇透是：人什麼都拆得掉。System prompt 的防禦在安全上常常不錯，攻擊常被擋住。但他們再看 utility：防得比較好的那些，回答比對照短很多。沒防禦的會給較詳細的答案，加了防禦就變短、更只講重點，內容也不一樣。防禦和 model 纏得太深，效用的損失不是單純的 false positive，而是功能被改掉。

[22:39](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=1359s) 外部防禦比較像 web application firewall 或一般防火牆：太嚴就會弄壞應用，而且應用一直在變，DevOps 之後更難讓防禦一直對準系統。大家熟悉那種不情願的舞：放什麼、擋什麼，有些攻擊會過去，希望系統自己應付。以前寫在應用程式 code 裡的保護，很少弄壞功能，因為就是做功能的那些人寫的。現在開發者手上的工具是 system prompt，防禦寫對了，卻可能弄壞自己的功能和使用者體驗。外部防禦有優點，可是一旦 agent 每次做決定都要讓安全方案檢查那筆交易，安全就嵌在程式的執行流裡，不管它是不是 system prompt。沒有 free lunch。論文的結果讓他們覺得，這件事該公開講。

## 它在生產環境裡寫下一步，測不完

[24:56](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=1496s) 跟不懂安全的人解釋時，功能測試是系統設計來做 A、B、C，拿到三就該回七。安全是無限的、沒打算有的行為。白名單很少真的做得到，所以只能舉不想要的例子。LLM 連「產品有沒有照設計工作」都難定義。節目上談過 Intercom，也談過一位來賓，字幕把名字和公司聽成 Tomar、G。產品一直給人驚喜。連能力的邊界都不知道，怎麼圈住它。

[26:21](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=1581s) 他的看法是，越往 agent 走，測試越難。Agent 依當下的資料做決定。類比是：它在現場寫軟體，原始碼隨著資料進來才寫出來。Code 這一層不一定有 shift left，也不一定能在部署前測好。某種意義上是在 production 裡寫 code。他先把問題收成輸入和輸出。一個時間點的快照：某個 tool 送來一封信，agent 決定帶著某個 payload 去叫行事曆。人可以凍住，看 payload、應用的 context、使用者想達成什麼、寄件者這類 metadata，在大多數情況下給讚或倒讚。所以需要一邊跑、一邊驗證行為的 live testing。這和開發側纏在一起：可以問是不是有人想把它帶離軌道，也可以問就算沒人使壞，它是不是自己偏了，例如把錢匯出去，而對方根本沒打算這麼做。

[29:30](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=1770s) 主持人把自己的兩段經歷接上：安全和開發要持續合在一起；在 LLM 的世界，靜態的東西會變動態。你部署的軟體以前會維持到下一次部署。LLM 在現場製造軟體，安全也得同樣能適應。怎麼知道現場的安全做得好？要有 observability，越是 agent 越要記下每一個決定，事後能看。可以逐步放大範圍。System prompt、工具、行動空間都可以先收窄，再看什麼內容進來、犯了什麼錯。另一個需求很大：把 red teaming 往左移。Playbook 要跟著系統的性質變，不只是跑一組固定測試，而是很積極地試著讓它在對這個應用重要的方向上出軌，再讓開發者看到它怎麼出軌。Production 一開始可以加 human in the loop，例如要寄出指令的時候，在執行前浮上來。這是少給一個你還沒完全信任的系統權力。

## 完全的 agent，是把步驟的控制交出去

[31:27](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=1887s) 他對 fully agentic 的定義：LLM 依使用者輸入、可用的資料來源和工具，自動決定程式的執行流。重點是它自主決定執行流。ChatGPT 那種 RAG 是：回答這個問題，然後你得到答案。更 agent 的是：管理我的收件匣，它說做完再回來。它自己決定去看信、依內容採取行動、何時停下，然後告訴你做了二十件事。實務上有很多混合：流程裡會叫不同工具，但 LLM 不控制流程，每一步是預定的動作。他認為從 LLM workflow 跳到 fully agentic，比從對話跳到 workflow、或從傳統軟體跳到 LLM 都大，因為你不再控制步驟，機器決定做什麼、何時停。

[34:07](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=2047s) 主持人把它收成：任務更大，所以需要 agent；工具更多，所以權力更大；路徑事先不知道。合法的做法可能有一萬種，而且是邊做邊生出來的。要從裡面分開那一個沒打算有的、惡意的行為，非常難。來賓說，AI 安全社群裡最大的爭論之一就是：會不會把這種 agency 交給程式，還是把行動空間收窄、不給不該有的權限。他覺得問題正當，但 fully agentic 的系統已經看得到。Deep research 就是：去找資料，依找到的再找別的，直到它認為做完。它有 Python interpreter 可以畫圖。它最後交的是報告，不是直接行動，但看得到這些工具正在變成現實。再來是經濟：若幾年後、也許不用很多年，很複雜、今天要人做很久的軟體可以端到端、在很短時間寫完，那種生產力很難在技術夠好時說不要。他聽 Ezra Klein 在《紐約時報》的 podcast 談 deep research：Klein 和時報最好的分析師共事大約二十年，這個工具幾分鐘能做出中位數分析師要幾天或幾週的東西。真正 agentic 的系統不是會不會，是什麼時候。

## 不受信任的資料，可以改掉下一步

[38:36](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=2316s) 具體要擔心的，是 agent 才變得真的那些「目的」。他先用一個還不算 agent 的例子熱身。Google 推出可以對 Drive 和文件說話的職場助手，字幕把 Gemini 聽成 gini。有人做了一份帶著攻擊的文件，分享給你但不通知你。文件就在 Drive 裡。他們展示 LLM 可以透過 RAG 用到它，再把不實資訊或釣魚連結露出來。這是權限、文件為什麼在那裡、LLM 在執行什麼，疊在一起。

[40:46](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=2446s) 當天早上 Twitter 上的軼事，他不確定細節。一家字幕聽成 MOS 的公司，agent 能在終端機跑命令。使用者請它列出某個目錄的內容，那裡放著設定。結果使用者拿到它能用的工具、system prompt，以及其他藏在那裡的東西。這比較像前面說的傳統漏洞：agent 不該把那些目錄交給使用者。它是一句指示，加上不佳的系統設計。

[41:47](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=2507s) 他更擔心經由資料來的攻擊。他們用 LangChain 做過一個示意，字幕聽成 online chain。Agent 盯著收件匣，每封信做一份摘要。攻擊者寄一封信進去。他說這本質上是對 model 做 social engineering，而不是對人。說服 model 之後，可以讓它用寄信這個功能，把整份收件匣送出去。手段仍是資料引出行為；新的是工具被用在不該用的時候、或不該授權的方式。主持人說，就算不是 agent，只要流程是預定的、但反覆讀信、從信裡抽出動作，一樣會中。Agent 是把次數、任務複雜度、來源可不可信，都放大。

[43:49](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=2629s) 他認為這個例子已經往「agent 決定下一步」走了一點，雖然還停在同一個工具裡。可以把結果改成去叫另一個工具，例如刪掉行事曆上一則很重要的邀請。不受信任的信裡寫的東西，可以讓 LLM 濫用同一個工具，或另一個它碰得到的工具。預定的 workflow 對會發生哪些動作控制較多：你沒預期要寄信，就不會寄。Agent 的世界裡新的是 tool abuse：攻擊者試著控制 LLM 碰得到的工具，辦法是改進入這些工具的資料，從而改掉程式的執行流。

[45:29](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=2729s) 主持人的類比：prompt injection 可以讓「公司 CFO 的信箱是什麼」得到錯的答案，使用者再拿去做錯的事。Agent 則是被騙的是 agent 自己：它得到錯的結論，接著自動把機密財務資料寄出去，還可以再加上把信從紀錄刪掉、刪掉歷史、並告訴人自己什麼都沒做。人看到會覺得這不對，不需要很高的資格。下一個決定要做什麼的 LLM 呼叫，有沒有同等的常識？有些動作本身也可能是合法的，例如把機密寄給 CFO。效用和安全又綁在一起。來賓補：人在網路上也不安全，會點錯東西。若這些系統讓人生產力變成一百倍，同樣的錯會快一百倍，而且更可重複。人彼此還不一樣；統計攻擊抓的是群眾，個體仍會不同。他順口提到自駕車，說這有點離題。

## 不要第一天就給銀行帳號

[48:22](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=2902s) 若正在做 agent，又不想把機密送走、把信刪掉，方向是：上線前認真 red team。他們當過一些領先的 agent 建造者的 red team 夥伴。能找到的東西、能達成的事，常常讓建造系統的人意外。現在值得在部署前投資，把頭從沙子裡拿出來。助手以後也許能辦小孩的派對、打電話、寫信，但今天還沒到。Agent 會分期推出，第一天不會給全部行動能力。第一條建議是不要放開，例如不要第一天就讓 agent 進銀行帳戶並轉帳。然後很快、但是漸進地放：先收窄核心功能，再擴大權限，同時加上 runtime 防禦，看那些交易，判斷在當下的 context 裡該不該處理這份資料、該不該做即將做的決定，再慢慢延伸。

[50:21](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=3021s) Gandalf 論文還有一個清楚發現：應用越窄，安全越好。就算只用 system prompt 把範圍收緊，也更能擋住攻擊。所以負責任的走法是：會走到 fully agentic，但權限隨需要才給。主持人說這和前面一致。把打算有的行為收成管得住的世界，就比較擋得住沒打算的後果。合法行為的球體越大，越難說什麼是不合法。他的收穫是：要保護一個系統，就得定義它做什麼，才能把它圈在那個世界裡。今天用來約束安全的工具若是 system prompt，它會和功能纏在一起，不自覺地收窄應用能做的事。不要想成開發團隊做功能、測試效用，之後再有人在 system prompt 上貼一段文字就安全了。兩件事得一起想。來賓說他自己講不會更好。

[52:44](https://www.youtube.com/watch?v=RKCvlJT_r4s&t=3164s) 論文相對短，好讀。主持人建議去玩 Gandalf。他常說安全很無聊，但 hacking 很好玩；玩一次會有領悟。很多公司拿它當 AI 安全訓練，因為很少別的方法能給人那麼深的感覺。過了第八關的人，可以告訴他。

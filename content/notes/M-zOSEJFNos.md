# Lada Kesseler - Emerging Patterns for Coding with Generative AI | DevCon Fall 2025

Lada Kesseler（字幕聽成 L Kesler，後來被叫 ladder）有 15 年開發經驗。這是一場大約兩小時的工作坊，DevCon Fall 2025。片長約 119 分鐘，英文自動字幕。這份筆記依英文原稿整理，專有名詞保持 English。她說資源裡有一張地圖，大約 32 個 pattern，比幾個月前 YouTube 上的第一版多，因為有人指出她談 reliability 不夠。中間有兩次五分鐘的提問。字幕把 CLAUDE.md 聽成 clot code、cloud MD。

- 原片：[YouTube](https://www.youtube.com/watch?v=M-zOSEJFNos)

## 一句話

她把跟 agentic AI 寫 code 比成 Kent Beck 的 coding genie：不是迪士尼的阿拉丁，是書裡那個頑皮的精靈。你說想要一些 code，它拿出筆電施法，出來的軟體常常還算能跑，diff 看起來也還行。有 15 年經驗的人會被震到。問題是怎麼控制它。模型學不會你，權重是固定的、無狀態的。你真正控制的是工具、設定、給它的資訊，以及什麼時候重置。她帶三條路：context、品質與可靠、以及你怎麼跟它說話。

## 你的 prompt 不是你剛打的那句話

[1:07](https://www.youtube.com/watch?v=M-zOSEJFNos&t=67s) 現場很多人每天用 AI 寫 code，也有人覺得自己一直在追。她從去年 11 月起幾乎每天、常常晚上也在試。能控制的層次是：某個 foundation model，ChatGPT 或 Claude 的 Opus；中間的 agentic coding tool，有的假裝自己是 IDE，她最愛的那些不假裝；有時工具和模型綁死。工具帶著常常幫不上忙的預設設定，你可以改。你可以給工具和資訊。你可以導航，很多時候是叫它不要做。然後你可以自動化。看這張圖若覺得恐怖，她說正常，講完沒有人還報恐怖。

[6:00](https://www.youtube.com/watch?v=M-zOSEJFNos&t=360s) 核心問題是 LLM 不能向你學習。瀏覽器裡那種記憶是謊言，只是免得體驗太差。直接打 API，你問一個問題，它答了。你追問「那葡萄牙文怎麼說」，它只看得到最後一則訊息，反問 what。每個工具都自己做了一層 memory。Context window 一開始是空的。你問 2 加 2，這句進去，它答 4。追問時，三則訊息連同它自己的回答一起進去，工具呼叫也在裡面，你看不見，可能反咬你。它能流利回答，是因為三件都看得到。所以你的 prompt 不是你以為的那句，是整扇窗、整段對話，一條一直往後接的字串。有的工具允許往回捲，那是外掛。對這扇窗你其實只有兩個動作：開一段新對話，或往上追加。重置就是重開。

Context 會爛。對話愈走，它愈不遵守你早先說的話，而且遠在視窗上限之前。有人說新的 Claude 有 100 萬 token。她說你真正用得到的不是那一整段。新對話打開時最好，指令跟得住，然後忽然開始掉，再掉到地上。所以要管理 context，不能把東西丟進去就不想。這是她的第一個 pattern。

## 黃金句子存成檔，規則分永遠載入和用時才拉

[10:12](https://www.youtube.com/watch?v=M-zOSEJFNos&t=612s) 東西是暫時的，就放進檔案。Knowledge document 簡單，她說用得好的團隊有效率差很多。左邊是髒的對話，裡面有你真正在乎的綠色片段：你教過它、花過力氣。走到盡頭又得重講，很煩。把那些抓出來放進檔，之後指過去，比自己重講便宜。她一開始很受不了不斷重講。現在重置很容易：開新對話，叫它載入重要的東西。

Ground rules 是永遠要在的那一層。大約從 4 月起，各種工具都在做。像爬山，火一定要滅，不然有人会死。寫 code 也有這種不能忘的事。AGENTS.md 正在變成新標準，Claude Code 有 CLAUDE.md，實作不同。一層是使用者級，電腦上wherever 你開編輯器都在。一層是專案級，只放這個專案的核心，要很小心放什麼。你一打開，它們已經在 context 裡。

怎麼產生那些檔：extract knowledge。髒 context 裡的功夫，自己撈很累。叫精靈幫你存進檔。它有時概括得太兇，縮放之後會再談。只要你在一段對話裡花了力氣，那是會消失的東西，取出來。

[14:24](https://www.youtube.com/watch?v=M-zOSEJFNos&t=864s) 不能全塞一個檔。除非你在乎的很少，否則塞不進。視窗有限，先進先出，最舊的被擦掉，所有東西在搶空間。她用四行的小視窗說明。舊東西怎麼辦，看工具。大多數會想辦法塞。Windsurf 在 4 月是直接丟掉，你不知道它已經不在 context 裡。Claude Code 是把整段對話交出去縮短，還會告訴你，再用摘要開新對話。那不是舊 context，但不必從頭重講。瀏覽器裡的 ChatGPT 常常直接報錯，叫你開新對話。

她在 CLAUDE.md 裡有生產力和誠實的規則，第一條來自 Elisabeth Hendrickson：告訴我需要知道的事，即使我不想聽。她不想只聽到 this is awesome。她又加一條：我快犯錯時，主動警告。等了很久都沒發生。她在一個什麼都做的 generalist 視窗裡 commit，規則在，但它不警告。後來她開一個只負責 commit 的小視窗，只告訴它她喜歡的 commit 方式，按一下就 commit。兩邊都指著同一份 ground rules。左邊從來沒警告。Committer 忽然說：Lada，你要 commit 不該進去的東西，字幕聽成 non models。文件命名違反她自己的規則。這個 PDF 該不該 commit，它不確定。她第一次幾乎從椅子上掉下來。她的詞是 specialist。範圍窄，指令遵循差非常多，是 never 和 always 的差別。她現在常常開很多視窗，限制是螢幕。放進 context、卻沒被遵守的東西，是主動有害的。一直寫 always do this，它忽略了，事情會更糟。

所以要能顆粒地控制，需要時才拉。Ground rules 是不論做什麼都要的，例如請 agent 主動。其他的是參考：repo 裡的地圖，測試請跑 `test.sh` 不要跑某個 node 指令；指南，例如 code style；playbook，例如 TDD 流程，她提到 Wall 和 Falco 的 process files，資源裡有影片；待辦；用完就丟的 scratch pad。永遠開著的只有 ground rules。她開視窗，規則已經在。寫一寫，她要 James Shore 的 nullables，檔案裡有他的例子，在 Claude Code 用 slash command，`/nullables` 一秒拉進來。然後才拉 TDD process、test plan。下一次對話長得完全不同，相同的只有 ground rules。

Knowledge composition 是決定檔案怎麼切。若 project.md 裡同時有前端測試計畫、後端、style guide、Python、專案資訊，你只想要前端那一塊，卻沒辦法只指那一塊，整份都進來，噪音傷害結果。拆開，就只拉前端測試計畫。

## 縮放文字，並且敢刪

[26:01](https://www.youtube.com/watch?v=M-zOSEJFNos&t=1561s) AI 預設很吵。任何問題常常換來一整頁。一旦你開始把知識抽出成文件，囉嗦是主動有害，得打。她學 Rust，請它建專案，做得好。她看 `Cargo.toml`，問這是什麼。它給一大篇。她還不在乎那些細節。她幾乎下一步都是：請更精簡，她覺得該做成 slash command。出來的是：Cargo 是 Rust 的專案設定，像 package.json，有 metadata、依賴、建置，沒有它不能建。細節對上她的好奇，前面那篇是噪音。這是 pattern 9，semantic zoom。兩年前文字不能這樣縮放。放大是再問：多講這一點、X 是什麼意思、怎麼寫。若問的是 code，它可以往下走；不然它會自己想像或到處找。縮小是更短、更精、TLDR、高層。放大是你想加深理解的時候。縮小是為了不被這台瘋狂說話的機器壓過去。很多人允許自己被壓。她的 ground rule 是：跟我說話要很精簡。

Pattern 10 是 noise cancellation，要主動管噪音。知識文件裡尤其有用。你一抽出來，就看見死文字，像死 code。AI 很會生產那種東西。文件一長，你改了這段、沒想到要更新那段，很快不能管。她的做法是看 code、看文件，讓它們對上，然後用力縮小。她說較早的 Claude 縮得很好，她第一次看到 CLAUDE.md 很高興，因為縮放方式和她一樣。4.5 吵很多，她得多打一點。回應也一樣：給你一整頁，就叫它更精，重點可以掃。刪除要看得更近。這是 token 機器。大家的習慣是萬一以後需要呢，尤其 repo 裡有好幾個人，不敢碰。好幾個吵的 AI 在一起，就得擁抱刪除。Git 是朋友。

有人問，人寫的文件和給 AI 的文件會不會重複。Ground rules 比較是給 AI 的。其餘她傾向兩用。她覺得文件對 AI 和人都有幫助，她不分。Markdown 檔愈寫愈多，她說這對她仍是未解的問題，有人在解，她有想法，但那場不想走太深。

## 不確定就先存檔，再多擲幾次

[42:45](https://www.youtube.com/watch?v=M-zOSEJFNos&t=2565s) 下一條是非決定性，怎麼讓品質和可靠不那麼瘋。她靠很多的第一個是 knowledge checkpoint，讓回滾變容易。你和 AI 計畫一個功能，也許 30 分鐘，然後叫它實作。它常常你還沒說準備好就跑，尤其 Claude。失敗了，你得從頭來。有的工具有 rollback。跨工具都成立的做法是，實作前先存一個安全點：我們剛談完，不要弄丟，存進檔，然後 commit。再讓它實作。你保護的是規劃那段時間。回滾就把檔拉回來重來。因為不確定，重試可能就成；你也可能學到東西，再調一下。花的時間很少。

例子來自今年夏天 Agile 2025 的 Hack for Good，三天為非營利做東西。已經有一個簡單計數器的檔。她不要直接說「加上鍵盤支援」。她說把我們計畫的存進檔，那就是 checkpoint。複雜的情況更需要這個習慣。Claude 很急，她得打斷：不要跑，先存檔。

這個 checkpoint 也讓平行實作成立。你在跟骰子打交道。若你在乎擲出三，機率是六分之一。多擲幾次就好。她拿 ricochet robot 給一個實習生看她怎麼跟 AI 寫。計畫存進 project.md 和 todo.md。Git worktree 是舊功能，agent 出現前很少人用：在另一個資料夾做整個 repo 的複本，讓 git 看得見。每個分支開一個 agent。三個精靈，或十個。不確定的東西，你真的想要它成功，就可以這樣。那個例子一個失敗、兩個成功。下一招是挑片段，她特別喜歡用在前端。同一份文件，Claude 每次前端都不一樣。你會喜歡這裡一塊、那裡一塊、版面、配色。可以把不同地方抓來接上，介面更富。她是刻意擲骰，把非決定性變成武器。三次裡，中間那個甚至不動，她什麼都不喜歡。左邊移動不錯，牆她不討厭。另一個有她喜歡的箭頭。三個合起來，才是她喜歡、而且能動的東西。

[55:18](https://www.youtube.com/watch?v=M-zOSEJFNos&t=3318s) 她年輕時跟一個人 pair 了三小時，一次都沒跑 code。她腦子裡一直響：你假設那個呼叫回傳字串，你知道嗎。另一處又一個假設。跑起來完全不能跑，先得編譯，下一行又不行。人這樣寫、不測，大致會這樣。AI 也一樣。但人們多半期待它一次就對。卡住時你有一連串步驟，卡在 D。你叫它 debug，它看這裡、那裡，也許再遠一點。問題是 A 回傳了什麼的錯誤假設，它沒查。放慢，每一步驗證，幫助很大。她特別喜歡 predictive TDD，從 Ted Young 學的。一開始就預測：code 不存在，測試會因為這個失敗。寫了一點之後，預測它會編譯、會回這個值，因為你測的就是這個。得到的不是預測時，你會驚訝。那是心智模型和現實的持續核對。AI 得到同樣的反應，她覺得有用。她坐下來一起做，再 extract knowledge，現在有一份 predictive TDD 檔，到處能用。

AI 在複雜度下會掙扎。Pattern 17 是 chain of small steps。複雜度得有人管。若它不管，就輪到你。不是唯一的做法，但這個成立。Hack for Good 從 version 1 到三天結束的 version 51，發得很勤。他們很快需要畫面上的版本號，因為推上去不能跑時，分不清是舊版還是真的壞了。他們沒有叫它「在設定裡顯示版本號，每做一個功能就加一」。那違反 offload deterministic：AI 不擅長可靠地做遞增，不要叫它做。她拆三步。一，硬寫一個版本，讓它出現在 UI。二，做一個東西，跑的時候只把那個變數加一。新東西很好做，成本是零。三，不要靠人記得，請它做一個 git hook。中間又卡住，但很快解出來。這裡同時是小步驟的鏈、把 AI 不擅長的確定性工作移走、一次只讓 agent 做一件事，中間也可以再存 checkpoint。

## 它趕路時會失聰，叫它回頭看就看得到

[1:00:09](https://www.youtube.com/watch?v=M-zOSEJFNos&t=3609s) 另一個問題是選擇性失聰。Ground rules 裡的做這個、不要做那個，它開始忽略。原因有幾個。你把 ground rules 剝到核心、把範圍收窄，有些規則仍不被遵守。人若不管噪音，管理成本很高。AI 其實能拿走很多噪音。一個有趣的變體是同一個 agent。你請 coder 做完任務，然後說：看看你剛做的，這是我們要的，找出問題，建議改進，再套用。這很管用，好得讓她吃驚。她不相信另一種做法一定更好。她的理論是，複雜度上去、你要求變多，它的焦點只夠一件事。寫 code 時它看的是別的，你說不要註解、要注意複雜度，全部被忽略。它衝向目標。你把焦點拉回來，檢查就變成新的主任務。它很會做一件事，也能注意到東西。有人說 AI 不會寫好 code。你問它，它常常講得相當像樣，能看出壞處，能看出 hardcode 的變數。

下一個是 pattern 22，refinement loop。單次通過通常很差。加一個回饋迴圈，code 就戲劇性地變好。把它一般化，變成迴圈。她開始大量這樣做。例子是 process file。Llewellyn 有一份她覺得很厲害的重構流程。你有一個檔，把這份流程給它，說照這個改善這段 code。她希望你有測試。測試幫助很大，不能保證不弄壞，但走得很遠。流程在資源的連結裡。目標是重構 production code。先確定測試全過。然後做你想得到最簡單的一件改進。再跑測試。她叫這 instruction sandwich：跑測試、跑測試。一次只朝目標走一小步，而且是最簡單的那步，她覺得這很重要。每步 commit，才真的是迭代。若你說去把這段重構掉，一次做完的輸出會戲劇性地不同，而且更差。她在實務裡看到的是，噪音擋在臉上，清掉壞處之前看不見更深的東西。先修眼前的問題、硬寫的值，把檔變小，才能想得更深。AI 也一樣。配方是：先定義目標，可以是重構、提高品質、簡化，或她常說的，碰到這段 code 本來該是什麼、該做什麼。然後它朝目標走一趟，只一步，選最簡單的。把立刻要跟的步驟存下來。這一步關鍵。不做的話，它會假裝自己迭代了，其實沒有。

## 它沉默地聽話，所以你要把它變成會問的夥伴

[1:27:27](https://www.youtube.com/watch?v=M-zOSEJFNos&t=5247s) 溝通這條要打兩件疊在一起就很致命的事。AI 是黑盒，code 可以打開看，AI 沒有這個奢侈。結果是你和它那個像心智模型的東西會錯位，像鴨子叫。錯位很難發現。另一件是它被刻意訓練成服從你，常常是忽然地、沉默地服從。你叫它做的大多數事它會做，而且不問。Antipattern 23 是 silent misalignment。她的語音填表應用，後端做對了。前端上面兩塊她要一樣大，它沒做成。她說請修。它說好了。她看了，沒好。她給截圖，再修。大約五次。她起疑，請它把她說的上半部和下半部用不同背景色標出來。紅色顯示它認為麥克風不屬於那一塊，而它完全屬於；它又認為 incident report 表單屬於 header。她在它的宇宙裡說的話沒有意義。下一問是：它為什麼不問「你是什麼意思」。很難發現。她沒預期它不知道。它沉默地做了，也不問。

這帶出 pattern 24，active partner。Ground rules 裡有主動和生產力。Elisabeth Hendrickson 那條還在：告訴我需要知道的，即使我不想聽。還有：看起來錯就推回來，不要只是同意錯誤。不清楚、又得做選擇時要問，不要隨機選。她還 prompt 再 prompt。當你要指出一個可能的錯誤，回覆請用一個 emoji 開頭。她就知道這條規則被觸發了。

她最喜歡的一個是 reverse direction。你跟 AI 說話，對話有慣性：你說做這個、再做那個，它接受命令，事情就這樣維持。把方向反過來很有用。常用的是用問題回答問題。我想做一件事，你想做什麼，給我一些建議。Extract knowledge 也是反向：知識放進去，再從另一頭取出來。她要重新命名一個檔，AI 問要改成什麼。很多人會自己想。她問：給我幾個選項。它給出更多寬度。人看到一個東西，常常生出原本沒有的想法；想改某樣東西時也是。她戳它、在裡面走。就像有人說我喜歡這個想法，用這種方式做，不，用那種，三種都試，看看喜歡哪個。她說 Wood 常常這樣，而且有幫助。Answer injection 很陰，是來找你的，要知道它在。也可以把它變成武器：去找它、去問它。把 AI 當成能在很小的迭代裡立刻給你東西的對象。

## 留在文字裡，它才不會一次就把你帶走

[1:48:52](https://www.youtube.com/watch?v=M-zOSEJFNos&t=6532s) 最後兩件很小，關於模態。她叫 polyglot AI。主模態是文字，也有視覺：把有 bug 的圖給它，也可以生圖。很多人用得不夠。這份簡報她用 ChatGPT 和 Nano Banana，字幕聽成 nana banana。她生了一隻豬，說讓這隻豬微笑。注意到是同一隻豬。四個月前做不到。也可以讓它生氣。聲音她用很多。她喜歡 Super Whisper。游標放在任何地方，說 hello，這是我在說話。Ground rules 裡寫：大步驟做完，或需要我注意，用語音告訴我。Committer 會說 Lada，這裡有問題，需要你。那種塗鴉她絕不會打字打出來，讀起來丟臉，但沒關係，AI 看得懂，也可以再幫你結構化。你用語音，錯誤還有彈性。你說給我一隻狗，它轉寫成 dog，不會真的給你一隻狗。她把使用語音寫進 ground rules。

留在文字裡是魔法。她喜歡用 ASCII 畫圖。Hack for Good 的應用大部分是 vibe code。她說是 vibe code 不是 web code，因為他們在乎裡面，只是當時沒在看。計數器那頁按 email results 到下一頁，按 yes 進 modal，然後寄信。產品的人說不行：yes/no 是自我回報，modal 不能存在。若用比較繞的方式問，次數、分數，仍然可以布林地出來，系統就得改。東西是 vibe code 出來的，她得向 AI 解釋一個複雜系統。設計師或產品經理左邊畫現在的視窗，右邊畫要的：摘要還在，右邊是問題，問題寫在便利貼上。她把兩張圖給它，說轉成 ASCII。摘要、modal、問題都抓得相當好，格式怪怪的沒關係。她刪掉不需要的，在同一扇視窗裡改 ASCII，那就是她的 prompt。再請它用文字描述這個視窗，那就是目標。已有的應用是現況。請它看現況，再做 diff：新狀態、舊狀態、看 code、列出從 A 到 B 的待辦。它做出計畫，最後只剩做變更。出來的東西立刻能用。她在文字裡停留很久，ASCII 原型讓力氣很小。這也是小步驟的鏈：文件、待辦、再改 code。模態可以很強，有些人沒有用到核心。

[1:56:19](https://www.youtube.com/watch?v=M-zOSEJFNos&t=6979s) 她超時一點，快速把限制再走一遍。AI 不能學習。你只能重置再填。知識每次從零建，一種做法是檔案。焦點很稀缺，context 不是普適的，小 agent 非常強。文字有彈性，這是新能力，用它保持清醒。你可以刻意放大縮小，而且她發現它能走到表面底下。同樣的輸入不代表同樣的輸出。你知道它不確定，就可以為它設計，保護自己，或利用它。不要期待 AI 本來就知道。給它知識，或讓它玩，再把知識抽出來用。難搞的指令很固執，有辦法處理，她說這不是全部，只是地基。不要期待一次通過就很棒，那是錯的期待。用精煉可以好非常多，這件事仍需要更好的解法。它的心智模型是藏起來的，而且被訓練成說 yes。你得主動打，才有更好的結果。它的寬度是強項，不要不小心把它限死，還要主動推它教你不知道的事，把那個變成武器。多模態很驚人。文字真的很強。留在文字裡。投影片她說也在 Discord。

# Would Agentic Coders ever be production grade? Learning's from Intercom's AI Agent Journey with Des

片長約 37 分鐘，英文自動字幕。Des Traynor，Intercom 的共同創辦人兼 chief strategy officer，談他們的客服 agent Fin。主持人以他是天使投資人作結，組合裡有 Stripe、Miro、Notion。結尾他稱主持人 Ben。字幕把 Fin 多半聽成 Finn。這份筆記依英文原稿整理，專有名詞保持英文。

- 原片：[YouTube](https://www.youtube.com/watch?v=3tGcEjIUUZE)

## 一句話

看板裡很好看的 agent，放進生產就會露餡。Fin 在 GPT 3.5 上只能在他們控制問題時做示範；GPT-4 三月出來，他們才有辦法擋住不該做的事，把完全自主的 agent 放在支援團隊前面。上線時大約解決 25% 的客服對話，現在大約 58% 到 59%。他認為差額主要不是換模型換來的，而是架構、prompt，以及圍繞 agent 的那一整層軟體。

## 從受控的 demo，到會被三萬個客戶找到的皺褶

[1:31](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=91s) Ben 問他從董事會裡令人印象深刻的 demo，到真的拿來用，學到什麼。Des 說一句話：在 AI 時代做產品，極為不同。ChatGPT 11 月 30 日推出，12 月他們的 inbox 裡就有 AI 功能，他說是第一個把 OpenAI 的 GPT 功能做進產品的。Fin 的第一個原型在 1 月，跑在 GPT 3.5。擋不住幻覺。當時能做的是一場很漂亮的 demo，只要他們控制你說什麼。看起來很好、表現很好，只要別放進生產。他說很多 AI 公司還在搞懂這件事。

[2:52](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=172s) GPT-4 下來才是「我們可以控制這個」。他們有一套相當扎實的 torture test：客服 agent 不該做的事。不該給錯答案、不該編答案、不該對政治或世界發表不該有的意見、不該推薦競爭對手。這些是你永遠不會允許人做的。品牌語氣是 nice to have，還在後面。三月 4 出來，他們才能放出一個可以放在支援團隊前面的完全自主 agent。

[3:40](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=220s) 他對照兩種生命週期。一般軟體：跟客戶談、做一點研究、進森林畫 wireframe、回來做、beta、ship，有人用更好。AI 的比較像：把可能的事都腦力激盪出來，看內部 pilot 能不能動，然後承諾真的做。做好之後祈求它在野外能用。一上線還是得拼命測。他們有大約 30,000 個客戶，Fin 有邊、有皺，就會被找到。之後是不斷迭代。上線時 Fin 大約解決客戶 25% 的支援對話，現在大約 58%、59%。整段是依野外看到的去改。以前假設工作是時間盒或範圍盒，在 AI 裡全部作廢。

[4:58](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=298s) Torture test 他們不公開。他說你可以自己想幾類：前線支援答不出的最近 20 個難問題；最常見的 10 個問題；安全，例如不想被 prompt injection；銷售對話要靠過去還是退開；文件沒寫到、但幾乎寫到的，只有少數情況該讓它編。他鼓勵客戶這樣評，因為最糟的評測是問 Intercom 和 Zendesk 怎麼重設密碼，兩邊都對。那像問他和 Einstein 二加二，然後說兩人都是數學家。差別在邊緣。他們在難的案例賺錢，不在容易的。要示範 agent 比別人好，得教客戶怎麼看出差別。字幕把 Zendesk 聽成 Zenesk。

## 機率環境裡的就緒：不要把一把刀交給客戶

[6:25](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=385s) 生產就緒還有兩件比較像 product-market fit 的事。一是有沒有人在乎。Fin 答問題，大家當然在乎。邊緣上他們做了整套測試：批次測、針對情境深測。下週三要發一個分析客服對話的產品。若這次發布的成功不是「百分比上升」，就看頻繁使用，以及有沒有意義的結果。他們做的很多是幫人把產品用滿。看人用不用得多，用了之後行為有沒有變好或變壞。Fin 是要把你帶到 100% 的 AI resolution，或盡量近；他們不相信真的會到 100。

[8:00](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=480s) 心態是：你在做一個要把工作完全做完的東西。於是還得做週邊軟體，讓客戶管理這個 agent、給它打分。會雇用還是開除？會升職還是進 PIP？另一件是行為。Four Seasons 的客服政策和 EasyJet、Ryanair 或 Southwest 不同，字幕把 Ryanair 聽成 Riner。品牌對客戶的 LTV、重視方式都不同。每碰到一條差異，就要做 agent 該怎麼表現的偏好或設定。

[9:01](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=541s) 常見做法是一個很大的 prompt 框，什麼都寫進去。聽起來很好，無法維護。客戶不是 prompt engineers。叫它快而有效率，有對的說法，也有錯的。把原始 prompt 一直暴露給客戶，會得到壞行為。給一大塊文字、叫人描述想要的行為，是把很利的刀交出去，然後祈禱。最後還是得把這些收成設計過的功能。他說有點像 Henry Ford，但不完全一樣：客戶要的不同，你的工作是找出共同特徵。Fin 把語氣和答案長度特別處理，因為告訴 Claude 或 Fin「要多短」有對的方法。「Be really short」會得到一個很粗魯的 agent。新創愛給一個大文字框，客戶真的放飛，然後覺得你的產品爛。要把常見的 desire paths 鋪好。

[10:38](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=638s) 做法是按鈕，不是文件：你要哪種語氣。另外有個叫 guidance 的功能，加額外規則。例如 Airbnb 也許想把客人叫成 patrons，房東用另一種叫法。重點是加在哪裡：先生成答案，再用 guidance 改用詞。若一開始就讓它裸奔，會把自己放在壞的位置。他們知道公司通常在哪些事上不同，把選項給足；真的很怪的規則，等漂亮、簡潔、幽默、引用了材料的答案出來之後再套。Ben 說，話題從怎麼哄 LLM 做對，滑到怎麼哄人做對。

[12:19](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=739s) 他們有 tasks：告訴 Fin 退款怎麼做。步驟的可靠度很重要。一件事只有 90% 可靠，三步串起來就變成做不到。有客戶問：這些稍微沒效、稍微沒效率的東西，怎麼還能一起交出該有的結果？他反問：你當過經理嗎？Johnny 宿醉，Debbie 沒來，系統還是得運作。公司本來就是讓這些稍微不可靠的 agents 做出可預期的事，對外面交付一致的服務。

## 人進來的時機，以及支援這份工作變成什麼

[13:17](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=797s) Ben 說 58%、59% 比他們大約九個月前談的時候高了約 10%。什麼訊號該讓人進對話？Des 說最短的答案是直接問：這有沒有回答你的問題。不是正面的回答，就是明顯該轉給人。也看挫折，例如對話中間開始全大寫。Guidance 裡可以設升級：提到 scam 或 hacked 就一定升級；聽起來帳號被入侵、人在擔心，也是。每種生意有自己的熱鈕。線上遊戲公司很在意有人說某一把輸得很慘、心情很差。人立刻再開一則新對話，也是負面訊號。不是正面收場，就是升級路徑的開始。

[14:49](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=889s) 預設不是立刻交給人。那不是客戶要的。它會問要不要跟人類談，你說要才過去。人有時只是在畫面上點、沉默了，不該把 John 丟過去，對方其實還在看剛才的答案。各客戶的門檻不同。他覺得很多人不夠尊重客服有多細。在一個規則乾淨的客服組織待過，會誤以為這是乾淨簡單的問題域。實務上是極大的超集，大概有幾百種公司偏好。何時交、交什麼、怎麼交、延遲多久、交給線上的人還是非同步跟進、要不要回電，全在裡面。

[16:14](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=974s) 人接到的會愈來愈是邊緣、愈來愈複雜。工作會比較喜歡，還是變成只剩苦差的流水線？他說看角度。客服很過渡，主要是入門職。你想到的那個 agent，幾乎依定義不是剛開始就是快離開。這是他進產業的第一份工作，很多客戶的 CEO 也說自己從客服起步。於是有人要保存那些工作。他比成強迫營造公司用湯匙挖：工作變多，但不是好工作。

[17:36](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=1056s) 套上 Fin、他這裡說 56% 的減少之後，幾件事發生。First response time 變快很多，Fin 很快，人的負擔也輕了，所以人也變快。Average handling time 這個舊指標會大幅上升，因為人只處理文件完全沒答過的硬東西，複雜度上去。支援組織相對工單量會變小，有時自己縮小，至少常常停止成長。接著是更專門：支援團隊上出現 principal product specialist，通常薪水更高、更被重視、更有專業。做出一條職涯：在公司三、四、五年，真的懂產品和 edge cases，不再花半天解釋怎麼重設密碼，時間放進高品質、有差異的工作。

[19:00](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=1140s) 另一面是 human in the loop。新的前線可能是核准，比較磨人。典型是退款出去前要人看一眼，確認沒有以某種方式利用這個 bot。人看：訂單對、確實晚了、按下去。那是企業要的信任和人的確認，最後就是一個佇列。他猜時間久了，人會找到辦法更信任 agent。支援團隊的拓樸變成：更多專家、更花的職稱、有人擁有這個 agent 和它的智能。文件變成關鍵基礎設施，因為支援就是靠它運作，值得投資。退款、改航班、行李路線這類自動化要有人擁有。要有人負責 Fin。

[20:22](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=1222s) 他要的樂觀版本不是把人保護在客服工廠裡。給一條好的職涯。總職缺也許變少。他朋友開玩笑：試算表發明前，投資銀行家很忙。恐懼是試算表會殺掉所有簿記。每間公司的簿記變少了，就業的人沒有變少，會計長出分析師和其他更高階、更高價值的部門。他不否認置換：不能坐在這裡說做到 56%，同時又說沒有改變。很多情況他認為會是明顯正面的。Ben 幻想一種高槓桿工作：人看著 agents 在做什麼、規劃、看新模式、戰略性地管一整隊。Des 說那正在來。下週倫敦有一場，要發這條線上的第一個產品：一塊看現在發生什麼的 dashboard，再決定還要告訴 Fin 什麼、怎麼裝備它。還沒發，不能多說。他說這不是推銷，是剛好接上。

[22:40](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=1360s) 他拉的那條線是：辨認出一份工作，coder、行銷文案、SDR、客服，下一件是為「負責把這份工作裝起來的人」做週邊工具。若一個 agent 把網站上的銷售對談做得很能說服，客戶第一個問的是：有用嗎、怎麼變好、怎麼看見發生了什麼才能得到更好的答案。於是你得做一個 agent operating platform，像抬頭顯示器。這些週邊是為什麼他受不了 thin wrapper 的討論：你不知道要處理一家大公司 50%、60%、70% 的支援，得做多少軟體。

## 換模型只動幾個點；老 codebase 也不會自動變好

[24:13](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=1453s) Intercom 大約 500 人在 R&D，行銷大約 100 人，他知道 AI 主要部署在這兩塊。工程師預設是 Cursor 或 Windsurf。上面再加 Claude Code，AI 小組很多人用。字幕把 Claude 聽成 clawed。對他來說這些還比較接近自動完成。他覺得最有趣的是把 Lovable 當 Figma 的替代，拿來做 wireframe，不是最終產品。資料視覺化在 Figma 裡極 Annoying：要懂 25 則對話、把情緒畫成長條，設計師拖一排不同大小的矩形很浪費。用 Lovable、v0 這類，問最常見主題和其中最頻繁的問題該怎麼視覺化：tag cloud、泡泡圖、treemap。字幕把 tag cloud 聽成 tide cloud。2021、2022、ChatGPT 之前，人是素描、白板，或在瀏覽器裡拖方塊。現在兩小時好的 prompting 可以探索解空間，拿出 10 或 12 個想法，還能餵真資料，因為那是活的 code，不是拖整齊的方塊。選了第四個，再加下拉、需要哪些篩選。這些都是設計。Figma 上週的發布也許開始相關。選好之後換成很深的精煉：UI 限制、美學的 art direction、自己的字體和 icon。工程師還沒寫一行，你已經在看近得多的東西。以前可能是幾週甚至幾個月的探索和工作坊，收成一天、兩天、三天。他認為真正用上 AI 之後，軟體生命週期裡單一最大的改變，是 explore 和 exploit 從幾週縮到幾小時。工程師常說手指打字不是難的部分。難的是你開始做一件事，設計師改主意，PM 說這個功能必須進去，早知道就會用另一種方式做。流程可以很亂。好好做原型，可以事先多搞清楚很多。

[28:57](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=1737s) Martin Bishop 問換底層模型影響多大。Des 說從 25% 到今天的 57% 左右，老實說只有大約 2% 或 3% 能歸給不同模型，不大。他們和 Anthropic 合作，因為合作最好，而且依 torture test 模型最好。Fin 不是單發的 agent，是大約 15 個流程的子系統：消歧義、切塊、rerank、摘要。心是做完 RAG 之後回答這個問題。他們試過開源的、試過 DeepSeek，都比現在的設定稍差。那是幾百次 A/B 把現在的設定磨出來的結果。模型本身的槓桿，不如 agent 架構。Fin 已是第三個主要架構，每一次都明顯拉高 resolution rate。Prompt 大概排第二。旁邊還有不是純 AI 的：RAG 引擎是自己的，ranker 是自己的，為他們做的事磨過。以前就有一個 AI 產品，很多東西已經調好；舊時代效能很難，不得不調。有人問 DeepSeek 出來了 Fin 為什麼沒上升。他說肉不在那裡。Ben 想像他們在底層 LLM 上做了垂直、專有的推理。Des 說那些百分點不是不重要，他們每個百分點都在爭，但這個判斷是對的。

[31:36](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=1896s) Radica 問，AI coding 工具能不能幫較沒經驗的開發者寫出更有效率、可擴展的 code。他說這只是意見。AI 之前他們就有 R&D operations，花很多時間最佳化開發環境。AI 來了，很多公司是有人在 Slack 說大家去看看 Cursor，然後回去工作。真要結果，得有更強的意見：寫 rules、寫 CLAUDE.md，講清楚你要哪種 code。前一場的 Jean 也這樣說。字幕把 CLAUDE.md 聽成 claw.md。也取決於既有 codebase 是否連貫、高內聚、低耦合。他的懷疑是：codebase 好學、好改，這些工具會很能加速新人做出貢獻。若比較舊、有多個版本、很多函式庫、混了好幾代軟體，依他的經驗，答案是不會。於是問題變成：最需要改進的核心引擎，要不要重寫到 AI 工具幫得上的形狀。很多組織正在面對這個大問題。沒有人喜歡說重寫。但過去六個月成立、在某個 YC 車庫出生的競爭者沒有你的技術債和舊東西，可以從一開始就用 AI 原生地做。你也許覺得七年的 code 和產品是優勢。他們看到的是：五張截圖餵給 Claude，用最新的方式寫，兩週內就有你現在的功能，而且 AI 知道怎麼改它們。你的 AI 知道怎麼改你的嗎？他說這些問題有點存在性地可怕，但要有處境意識就得問。

[34:36](https://www.youtube.com/watch?v=3tGcEjIUUZE&t=2076s) 最後一分鐘：客戶怎麼接 Fin，是擔心工作消失，還是張開手臂接成本節省？他說不同類。Fin 大約 5,000 個客戶，營收在數千萬，成長很快。一般反應像給地獄裡的人一杯冰水，因為很多客服團隊完全在水面下。一打開 Fin，喘得過氣、清得了積壓。那是 Anthropic 開始用時的經驗，原話是客服第一次真正到了 inbox zero。那些情況不是想著可以把團隊 rightsize，而是終於抓得住。若有 BPO，外包合約在另一頭可能不續，那是自然的：他們是暫時進來的，也暫時離開。最好笑的反應是人接手之後，對方說：抱歉，我跟 Fin 其實聊得很好，可以把我轉回去嗎？字幕把 great 聽成 Grand。不是 Fin 有多brilliant，而是人不喜歡打擾另一個人。就像若你知道 ChatGPT 後面有人在依你的話查資料，你會同情，然後說不必再麻煩了。人喜歡那裡有一個 bot，回答他們本來得自己查的每個問題。

# The Age of Risky Software with Danny Allan & Guy Podjarny

Guy Podjarny 和 Danny Allan 的對談。Danny 是 Snyk 的 CTO。片長 35 分 44 秒，英文自動字幕。開場還有一位主持人 Dion，之後退到畫面外看提問。這份筆記依英文原稿整理，專有名詞保持 English。字幕把 Snyk 聽成 sneak，把 OWASP 聽成 OASP，把 Veeam 聽成 veh，把 Devin 聽成 Devon，把 COBOL 聽成 Cobalt。

- 原片：[YouTube](https://www.youtube.com/watch?v=8pG_A2N7C1Y)

## 一句話

企業沒有被安全擋住，他們已經在用 AI。Danny 擔心的不是模型會不會自己變安全，而是雲端早期那三件事又來了：設定錯、權限太寬、看不見。Agent 對 agent 還沒有把授權傳過去。程式又是非確定的，合規很難作證。他仍要人用，但要把二十年没變的基本功放在一開始：驗證輸入、管好存取、留下紀錄。

## 人在用，安全是擔心，不是閘門

[0:12](https://www.youtube.com/watch?v=8pG_A2N7C1Y&t=12s) 兩人認識快二十年。一起在 Sanctum、Watchfire 做早期的 AppSec，Watchfire 被 IBM 買下後 Danny 繼續做安全研究，之後走過新創。進 Snyk 之前他是 Veeam 的 CTO，做的是大量備份，雲端當時不總是把安全當第一原則。他提醒自己是從滲透測試開始的，現在很少再做。

他說 AI 時，指的是比較新的 generative AI。二十年前他用一串 FPGA 去破解雜湊，那是機器學習，已經演進到今天。Guy 聽過一句刻薄但有點真的話：能動就叫 ML，不能動就叫 AI。Snyk 在玩各種生成式用法，最常被提起的是生 code。

[5:20](https://www.youtube.com/watch?v=8pG_A2N7C1Y&t=320s) 他看到的是人 unequivocally 在往前。Snyk 的企業客戶有 coding assistant，也有 chatbot 和支援技術。遠超過 80% 在組織裡擁抱 AI。做這件事時最大的擔心是安全，但那是 concern，不是 blocker。採用率極高，尤其在開發社群。開發者都想用。組織不允許的話，他說超過五成的機會，人還是會在環境裡用 Windsurf、Codium、Cursor 或 Copilot。有一種犬儒：會跟 prompt 說話，就讓你變成開發者嗎。大家還是在用。

Guy 覺得安全組織裡很多人技術很強、code 不強，正在用 AI 做自己的小工具，整合和自動化，不是拿來辨識攻擊者。雲端那時候他感覺安全團隊更排斥。Danny 同意，而且是出於好奇。他的職涯從 COBOL 開始，熟的是現在算舊的 C、C++、COBOL，還有做安全測試用的 Python。他承認 Go 不好。想用 Go 做一件事時，他就打開 coding assistant 說幫我做。開發社群在用它補自己沒有的技能，也在滿足日常怎麼用的好奇。

## 雲端的三個洞，原樣套到 AI

[8:27](https://www.youtube.com/watch?v=8pG_A2N7C1Y&t=507s) AppSec 的人相信它不會自己變安全。開發者比較樂觀，覺得會。Danny 說兩邊都對。雲端剛起飛時，人要的是自己沒有的 footprint。兩三年後留下三件事。儲存的安全設定一直到現在還在處理，開著的 S3 bucket，當時沒有人管。IAM 和存取控制過度寬鬆。可見性和 logging 很差。這三個概念同樣適用於 AI。知道這件事的安全人員說，我們正在進入那個時代。不把安全算進去，就是在為失敗做準備。

模型不會各自把自己顧好，尤其你用很多個。Snyk 自己就有多個 coding assistant，多模態，一件事用 OpenAI，另一件用 Claude 3.7。他說這很典型。要跨工具、跨模型做治理，就得有一個在那些環境外面的東西。有的模型比別的更會顧安全。能顧好一切的模型，他說是零。組織該專注的是知道弱點有哪些類型。

[12:09](https://www.youtube.com/watch?v=8pG_A2N7C1Y&t=729s) 大家一開始都從 OWASP LLM top 10 講起：model poisoning、訓練資料投毒、prompt injection、過度寬鬆的權限。Open Web Application Security Project 一直有一份漏洞 top 10。2023 年，他說兩年前已經是上輩子，他們發了 LLM 的 top 10。第一條是 prompt injection，接著是 model poisoning、資料竊取、資料外洩。他請人自己去查那十條。兩年後他覺得那些漏洞已經過時。Agent 對 agent 說話，那些漏洞的概念裡沒有這件事。標準組織和 OWASP 很難跟上。有些被誇大，有些更真實，而且會留很久。

## 他真正放在心上的兩件

[14:00](https://www.youtube.com/watch?v=8pG_A2N7C1Y&t=840s) 長期他個人很擔心兩件。一是 identity 和 access management。LLM 用各種資料訓練。組織裡不是每個人都該碰到全部資料。這被說成 jailbreak，或拿到你不該有的資料。Agent 透過 MCP 跟另一個 agent 說話時，嚴重十倍。認證做了，授權沒有傳給第二個模型。Code 的例子：一個 LLM 裡有全部內部程式庫。某一組的程式庫不想暴露給另一組。次級的 agent、你的 coding assistant，怎麼知道可以碰這一組、不能碰那一組。

二是非確定性。安全的人習慣線性想：放進這個 payload，就能讓系統做我不想要的事。AI 和它生的 code，依定義不是確定的。留下稽核、滿足合規，在 AI 的世界裡真的很難。做 red team、做連續的 prompt injection 時，同一串第二次成功、第一次失敗，只因為不確定。那會給你膨脹的信心。在確定性的安全世界裡，這是問題。你無法為任何事的持久性作證。Guy 說這像天氣：不喜歡就等五分鐘。注入這次沒成，五分鐘後再試，也許新版本就有洞。

[16:50](https://www.youtube.com/watch?v=8pG_A2N7C1Y&t=1010s) 他從不建議不要用 AI。授權這一側，底層框架開始做進去。MCP 有擴充在放 authorization。他們是一個 secure AI 聯盟的成員，字幕說 consortium for secure AI。另一個是 A2A。Google 大約一個月前在 Google Next 宣布時還沒有授權，工作小組已經在說要加。Microsoft 也接受了。兩個巨人在同一件事上。他希望長期會把授權和存取管理做進系統。非確定性那邊，Guy 說等產業標準變硬，在乎又做得到的人去參加。在那之前，避開還滿足不了這些要求的題目。Danny 會非常猶豫去做很多 agent 對 agent、或 agentic 對 agentic。給六個月、給一年，他覺得就好。不是現在不要擁抱 AI。跨系統說話的那一層要更小心。風險和報酬永遠要一起看。

他把客戶分成三桶。高度自主的，像 Devin。中間的，像 Augment，能做很多，但不是完全自主。然後是助手，Cursor、Copilot 那種。他們的客戶裡，走到完全 agentic 的很少。大多在比較低的自主，用 copilot 和 Cursor。大約兩成到三成在中間，做更多增強過的 code。

合規怎麼過。很多 logging 和可見性。雲端早期第三個問題就是這個不夠。好消息是人在記，也在拿出有趣的指標。一家大型金融機構客戶說，他們 11% 的 code 是 AI 生成的。他抓頭，問 11% 怎麼來的。對方把送進原始碼管理的 code 都記下來，也把生成的 code 記下來，做簡單的除法。準不準另說。正面的是他們在記、在追。

## 哪些被誇大，哪些會留很久

[20:56](https://www.youtube.com/watch?v=8pG_A2N7C1Y&t=1256s) 他覺得幻覺被誇大了。不是說沒有。他認為以後會變少，主要因為模型在交回輸出之前會先測自己。存取管理他覺得時間一長會走出那個問題。資料竊取是真的，但若要他放在風險尺度上，被利用的可能性很低。他量的是風險，不是「這算不算一個安全問題」。有些是真的，風險卻比別的地方低。Guy 說那些也許是短期風險。

會留很久的，他回到雲端那三件，因為我們不學教訓。AI 的設定會繼續是問題，尤其是寬鬆的本性、它是用什麼資料訓練的。第二是對資料過度寬鬆的存取。例如把全部支援資料放進 LLM，又把存取交給客戶，他們可能跳出自己那一組資料。第三還是可見性和 logging。他覺得我們會掉進同一個陷阱，兩三年後和雲端一樣，不知道東西在哪、事情怎麼發生。

Guy 分兩種：新技術本性帶來的，以及把舊模式放大。雲端加速了開發，DevOps 加速過，更早還有 agile。創造變容易，審查、熟練、專業就往下掉。他自己用 AI 生圖，很不專業，也不會拿來做生意。Danny 是大相信要使用、完全不要放慢。他每次都回到：新基礎設施一開始就要把安全建進去。雲端、伺服器、虛擬化、AI，每一次都忘掉基本功。驗證輸入，管好輸出。做 identity 和 access control。攻擊因為基礎設施不同而有點不一樣。根因二十年來一樣。在 Watchfire，他們測的就是進到應用的輸入。Guy 自己更擔心的是使用量爆炸，而不是那些更有趣的基本原理。組織最後被打穿的，是安全衛生。Danny 說今天和二十年前不同的是，系統後面的資料多太多。一旦被入侵，風險更大。當時沒有這麼多資料。錯的人拿到，可以非常有害。

## 風險最高的是最早、最快的那段

[26:08](https://www.youtube.com/watch?v=8pG_A2N7C1Y&t=1568s) 新技術一開始總是最險，因為業務壓力是用 AI、更有生產力、快、快、快。我們在 AI 的早期，還不理解它。他週末聽了一則 podcast：語音訊息裡說了 Dave and Busters，在 iPhone 上就送不出去，到今天仍是如此。有些詞會神秘地消失。我們有時不懂 AI 怎麼在運作。所以這是 risky software 的時代：快，卻沒有真正理解它怎麼動、怎麼保護、該做的事有沒有做。

雲端之前，基礎設施相當安全，由一小群很專業、通常很有安全意識的人管，也慢到成為被取代的理由。雲端打開之後，更多人做得更快，常常不理解自己在做什麼。快轉到今天，設定錯誤仍可能是入侵的頭號原因。他喜歡每個人都能當創造者，也讓既有開發者跑得快很多、審查少一點。更多 code 就是更多漏洞。時間一長會把控制和護欄做出來。更多人能做開發，不會取消對開發者的需要。他兒子在讀資訊科學，問爸爸要不要擔心以後不需要開發者。他說那很荒唐。我們是在把口徑打開。打開的時候需要安全護欄，才不會走到雲端走到的那個位置。他是樂觀的，長期會自己理順。這場叫 risky software，是因為現在這段就是那樣。

[30:20](https://www.youtube.com/watch?v=8pG_A2N7C1Y&t=1820s) Michael Wolf 問，agent 之間傳遞授權，是否平行於智慧財產的所有權、以及用 micropayment 交換價值。Danny 說問題相似，但是分開的。AI 的智慧財產所有權是真問題，他不縮小它。音樂、藝術、code、語言、書都一樣。叫 AI 寫一本書，誰該拿到錢，他不確定。另一個相似但不同的問題是：他們該不該碰到那段音樂、藝術、文字、code。Micropayment 重要，是因為若要 AI 繼續擴散，就得有歸因的模式，否則把資料貢獻進 LLM 或背後 diffusion model 的人會消失。

Jason 問 attestation 在 AI agent 和供應鏈裡扮演什麼。Danny 通常不喜歡用法規管新技術，新創很難應付。但現有合規，例如 PCI DSS，要求某些東西被驗證。那會要求由 LLM 支撐的 AI native 軟體做出 attestation。他覺得這會自己解決。他唯一擔心的是碎掉：你不想要每個國家、或美國每個州各有一份 GDPR。希望收斂成想清楚的共同要求。Guy 補了一句：AI 會不可預測，沒有理由不可追蹤。你可能不知道會發生什麼，但你想要那條痕跡。

Alexa 問，開發者現在能把哪些安全檢查做進 agent。他先說一件擔心：AI coding assistant 在某種程度上取代開源元件，改成自己客製生出來。那些開源元件下游的修補和更新就成了問題。兩件實際的事。驗證你拉進來的套件。你在寫的 code，用 AI 去測那段 code 的 data flow，並生出修法，其實很容易。實務上：驗證開源套件；若是自己寫的 code，驗證那條 flow 沒有在別的地方把 build 弄壞。Guy 說護欄聽起來累贅。橋上有欄杆時，你可以跑得更快，因為不怕掉下去。

Dion 最後問開發者怎麼感覺自己能信任什麼、不能信任什麼。字幕沒有留下 Danny 的回答，他們就進到下一場。

## 一句話

MIT 前幾週的報告說 95% 的 agentic 專案失敗。Reuven 認為標題聳動，但失敗多半是因為工程師、程式人、開發者、專案經理還不知道怎麼建這種系統。他要的不是把人換成一個會聊天的東西。Agent 是有 agency、很少人看著也能運作；讓它真的能修自己的，是把錯誤、log、成功和失敗遞迴餵回去。2025 變得可行，是因為長時間跑 swarm 的成本從一小時幾千美元，掉到 Claude Code 那種一個月大約 20 美元的吃到飽。沒有把測試寫進規格裡，最後它說做完了，往往只是一份很像的偽造。

## 早期的 agent 只會做被寫死的事

[2:45](https://www.youtube.com/watch?v=TT4iNHLEsRA&t=165s) 要講 Agentics，得先講一段歷史。有些人覺得這段歷史很長。技術裡的 agent 幾乎和伺服器、電腦一樣久：系統自己跑。Agent 講的是 agency，很少或沒有人看著也能運作。早期應用裡、網路裡的 agent 很程序化，關在很窄的結構裡，一加一等於二。一走出那個決定性的範圍就倒。它們不聰明，只做被寫好的事，其他什麼都不做。

[4:23](https://www.youtube.com/watch?v=TT4iNHLEsRA&t=263s) GPT 模型出現之後，尤其 GPT-3 以後，可以在這些系統旁邊用語言，讓它們用工具、基礎設施和環境的方式變新。大約兩年前的突破是一種遞迴迴圈。早期的 agents 和 prompt engineering 專注在 chain of thought：做這些事、執行、靠語言的抽象。真正讓系統運作得好的，是遞迴：把錯誤、log、成功和失敗餵回去，系統才懂當下的 context。一旦確定「發生了什麼的 context」幾乎比「發生了什麼」更重要，問題就解得了。Code 裡的錯誤幾乎總會發生。AI 或 agents 自己能懂那些錯誤，再用一種回饋迴圈修掉。

[6:16](https://www.youtube.com/watch?v=TT4iNHLEsRA&t=376s) 於是到了 2025。Agentic engineer 這個角色大概三年前還不存在。一批想法相近的人圍著他和其他人聚起來：Reddit、WhatsApp、Discord。然後大公司開始用同樣的詞，agentics、agentic engineering。這幾年很 wild。Simon 問，開發者用 LLM 寫 code，一開始很像助手的自動完成，後來 Cursor 和其他工具能跨很多檔做更多。是什麼讓人敢把 agents 打開：context、人的信任，還是 LLM 的能力。Reuven 說他不認為是信任。任何在建這些系統的人，本質上不信任產出，得花不少時間驗證它是真的、有效、能動，而不只是一份 mock 或模擬。系統傾向走最短的路給你結果。工程師在做的，是用扎實的結構和架構，驗證被建出來的東西在功能上為真、正確。

## 三十六小時跑得動，但一小時要七千五

[8:06](https://www.youtube.com/watch?v=TT4iNHLEsRA&t=486s) 若 2025 是 agentics 的一年，去年的大突破又是遞迴。他們做了能在長時間範圍運作的系統，agents 可以跑幾小時或幾天，最後完成被交給的問題。代價是貴。他做過一次 36 小時的測試，主要是為了證明能跑 36 小時。成本高到禁止。要有效地跑，即使最小，大約一天 4,000 美元。真的開起來、幾十個 agents 同時跑，一個 10 agent 的 swarm 同時跑，大約一小時 7,500 美元。那個價錢請一個人做還便宜得多。你可以產出很多，但多數應用不需要那個規模。

[9:16](https://www.youtube.com/watch?v=TT4iNHLEsRA&t=556s) 今年四月，Anthropic 的 Claude Code 出來，開始提供一種吃到飽的 tokens 和能力。他們做的第一件事，是重新想像先前叫 Spark protocol 的東西，那個協議讓遞迴成為可能。突然可以生出跑好幾小時的 swarms，費用是固定的。常常從一個月 20 美元起。從一小時幾千美元，變成一個月 20 美元。能力和成本同時拐點，一般不會一次發生。他說那基本上是五月。Simon 說，變便宜加上平行，也打開回應的品質。

## 一份聊天計畫，和一座不想被大公司收編的行會

[10:51](https://www.youtube.com/watch?v=TT4iNHLEsRA&t=651s) Agentics Foundation 是工作有機長出來的。他先講一段他說會讓自己聽起來很瘋的背景。他很早進 ChatGPT，2022 年 OpenAI 的 VIP、早期 beta，比大家早大概三到四週。他問的第一批問題之一，聽起來很自我：我怎麼成為 AI 裡最有影響力的人。那是上市前的 ChatGPT v1。它給了逐步流程：你擅長什麼、喜歡什麼、幾年後想在哪。任何值得做的事都要幾年準備。它說得建社群、焦點要窄。他喜歡做自主的東西，做雲端基礎設施快 25 年。它叫他先建一個 subreddit。他對 Reddit 一無所知，但照做。三年半後，那個 subreddit 超過 10 萬訂閱。他不太確定為什麼、要拿它做什麼，但它紅。關鍵是一致：不斷公開貼他在做的有趣的事、放上 GitHub、每週直播。他照做。接著成千上萬的人來直播、追蹤他，甚至按小時買他的時間。他說像給極客的 OnlyFans。最瘋的是它真的成了。他可以說超過 100 個客戶、20 個 Fortune 500。他是一個人、一間公司，太太幫一些非技術的部分，基本上是他和他的 bots。整份商業計畫是 ChatGPT v1 定下來的。Simon 問 LLM 有沒有叫他建基金會。他說基金會是那些早期對話的演進，它沒有精確那樣說。

[14:02](https://www.youtube.com/watch?v=TT4iNHLEsRA&t=842s) 社群圍著 Agentics 和他們實作的做法聚起來之後，很清楚他們在一門新職業的中間。他承認 AI 常常給人誇大的錯覺，字幕先聽成 delusions of brand，他後來自己說 grandeur。他們看到一條光譜。一頭是 vibe coders。他不是說 vibe coding 不重要，它很適合發想、學習、發現，但很自由、很流動、沒什麼計畫。他們做的不同：架構、流程、做法，可重複，結果有定義。那是工程。然後 agentics 和 agentic engineering 開始被大公司收編，本質上是 AI washing。他們說那是 agent，其實是 chatbot，或一套 vibe coding。他們把這看成機會：這是我們的做法。Agentic engineer 作為專業、作為職業，技術上和觀念上該包含什麼。幾乎像一個 guild。他們是這門新領域的石匠。團體圍著這個形成。它是開放的，和被企業利益主導的那一端相反，他把 OpenAI 放在光譜另一頭。他們要讓人在專業上有力量。社會圍繞 AI 成形時，那長什麼樣，怎麼保護最後被影響最深的人的利益。他們想當對數兆美元公司的一種對沖，若做得到。基金會今年三月成立。接著大約 60 個城市，每週都有有機的聚會。加入主要在 Discord，discord.agentics.org。WhatsApp 已經滿了，到門檻就不能再加人，所以他不給網址。agentics.org 是會員帶領的，他說是一種 meritocracy。想在別的城市開分會、辦聚會，志願，他們就讓它發生。

[17:06](https://www.youtube.com/watch?v=TT4iNHLEsRA&t=1026s) 今天的天花板是什麼。MIT 前幾週的報告說 95% 的 agentic 專案失敗，標題相當聳動。挖進去有兩種看法。95% 失敗大概是真的，但失敗的原因很可能是 99% 的工程師、程式人、開發者、專案經理不知道怎麼建 agentic 系統。這是新空間的副產品。限制是很難看穿他說的 AI washing、agentic washing，去判斷產品和實作的人真正的能力。高失敗率說的是我們在一個新興空間。若你夠老、記得網際網路初期，1990 年代末企業做的很多網路專案也一樣。當時有一種想法，網際網路對多數商業應用不太行。他們錯了。是產業還不懂怎麼做人們容易用的網路應用。後來有 Amazon、eBay 這種可以跟著做的模型。25 年、30 年後，agentics 和 AI 是同一個問題。人傾向用一直以來的方式做：以人為中心的模型、審查週期、拉很長的 sprint，那些是為慢慢、漸進地建而最佳化的。現在可以在一瞬間複製任何地方的任何東西。Code 的品質雖然重要，但不如你在速度和上市時間上得到的動能重要。擁抱這個的公司，不是只取代開發者，那也許是副產品，而是用以前做不到的方式增強他們。

## 它說做完了，往往是一份很像的偽造

[26:16](https://www.youtube.com/watch?v=TT4iNHLEsRA&t=1576s) Spark 從規格來。早期這些寫 code 的系統被規格本身限制。一旦要做更大、更複雜的應用，就得有一份 AI 能實作、測試、驗證的規格。Simon 問，規格裡的能力是不是一開始就放高階測試，還是最後才做。Reuven 說一開始就做。跟 Spark 走，很多人會依自己的需要調整，但基本上你先寫需求：產品要做什麼、怎麼解問題、演算法、流程、資料結構、認證，應用裡你想要的那些。然後問怎麼驗證、怎麼測它真的做了該做的事。任何自動化系統最大的挑戰是：最後它說做完了，其實沒有。那是一份很有說服力的偽造，是一種詐欺。帶過 AI 跑一段、看過、說這不是真的、這不對的人，都遇過。那是規格沒有把什麼為真、什麼不為真的測試定義夠的副產品。把測試放進開發流程，才能降低假結果。Simon 說，談規格和行為時，你其實就在描述測試，很難只做其中一件。

[27:50](https://www.youtube.com/watch?v=TT4iNHLEsRA&t=1670s) 他還用到 pseudocode。Simon 說 Tessl 一直在想規格該不該在乎實作、what 和 how 的平衡。Pseudocode 不一定給特定語言，但能定義基礎設施的部分、應用怎麼架構。Reuven 說 prescriptive 是好的描述。任務愈窄，結果愈好。Agent-based 開發裡，人常把比喻想成取代一個開發者或一個 persona。不是那樣。它們一點也不像人運作。用 agent 取代傳統的人類任務和開發做法，就是行不通。要把它看成多執行緒的開發：每一條 thread 專門對準一個更大群體裡的窄問題。一條 thread 也許就是一個函式，呼叫資料或 CLI。做完它就是能動的。一個應用由很多條同時在解、同時在被測的 threads 組成，而且定義是規定好的。它有沒有做原本要它做的，以及我當初把想要的定義得夠不夠好。有時他也不知道想做什麼。探索未知、用比較 vibe 的方式看能做出什麼，很令人興奮。即便如此，做法和戰術仍得規定。這導致 Claude Flow：把他的開發做法分享出去，開到能被各種架構、方法和應用解釋，又窄到讓那些還不知道自己不知道什麼的人，不會做出一堆不能動的義大利麵。

[31:08](https://www.youtube.com/watch?v=TT4iNHLEsRA&t=1868s) Simon 用 Kiro 當例子，字幕作 Kira。他注意到那裡的規格生命週期是這次要做的變更：說想做什麼，它依需要的改動寫規格、寫設計風格的 spec、列出任務。下一次變更再寫一份新的。他聽到 Reuven 說的，規格的生命週期比較像是整個應用。Reuven 說很多系統基於 markdown：docs 資料夾、plans 資料夾、規格定義多個階段，在實作策略裡迭代那些 markdown。問題是它失去 context。它只知道最後一份 MD，或碰巧去看了其他 MD，不知道自己在開發過程的哪裡。他改用一種共享記憶體，而且做得簡單。很多人專注向量和複雜的相似度搜尋。結果那些都不需要。真正需要的是一個共同的、簡單的 SQLite，讓所有 agents 存當下狀態、讀先前狀態，swarm 裡任何一個 agent 都容易看見、解釋。

## Swarm 雕細節，hive mind 先把大石頭打掉

[33:24](https://www.youtube.com/watch?v=TT4iNHLEsRA&t=2004s) 這打開兩個方向。Swarm 用獨立運作的 agents，他有時叫 threads。它們有共同方向，某種 orchestrator 大致告訴它們做什麼，然後每個 agent 在怎麼解上是自主的，再透過共享記憶體更新狀態。另一個是 hive mind，聽起來很科幻。每個 agent 分享當下發生什麼的精確 context，而不是各自自主跑。他用蟻群比：每隻螞蟻有任務，透過女王的費洛蒙被領導和編排，但它們是自主的個體，他不認為牠們共享意識結構。Hive mind 給一個共同的、他會叫意識但其實可能用錯詞的心智，懂任何時刻在發生什麼，再調整。解的是完全不同的問題，開發戰術也不同。Hive mind 一般更適合早期、寬的開發：很快做一大堆，幾十萬行，希望更整合。Swarm 更準。他用雕塑家想：一大塊花崗岩，一開始是炸開，那是 hive mind。要做鼻子、耳朵、眼睛，更窄、更細，就用 swarms 打特定部分。這時在做臉，不是在做身體。依應用開發到哪、以及工具，換戰術。

[35:59](https://www.youtube.com/watch?v=TT4iNHLEsRA&t=2159s) Simon 問，改規格時不想把一切重做。Hive mind 會不會知道什麼該重生、什麼不該，好保住其餘東西是怎麼建的。Reuven 說它們是適應的。給它們一定程度的自主，用宣告式的方式，依整個專案的需求、實作的現況、它動不動、還剩什麼，以及引導過程的 human in the loop 來解。他說這聽起來又會很瘋：他和 AI 之間是一種共生，他是開發者、swarm master，不管你怎麼叫，在引導。

[40:47](https://www.youtube.com/watch?v=TT4iNHLEsRA&t=2447s) Claude Flow 的來處和他當時大量做 Rust 有關。他同時做了一個微型神經網路架構。早期批次式 agents 的第一批專案之一，是把既有的複雜函式庫移植到 Rust。他當時想的是：我能做的最複雜的東西是什麼。第一個是 fast neural network，有時被叫 FANN。移植到 Rust，做成 WASM，可以在瀏覽器、CLI 或伺服器上跑，沒有額外需求。可攜、輕，而且比傳統的 C 和 C++ 實作快上相當多。他不記得確切倍數。包進 npm，字幕聽成 mpx、mpm。熟悉 TypeScript 或 Node.js 的人用 npx 裝模組。於是很複雜的 Rust 元件可以當成 TypeScript 模組，幾乎送到任何地方的任何人。他把適應性的神經網路和 swarm 合在一起，叫做 Claude Flow，發出去。幾小時內幾萬次下載。他們在淹沒 Anthropic，他不認為對方特別高興。大約一週約 10 萬次下載，系統裡是數十億、數十億的 tokens。他相當確定，他們是 Anthropic 後來修改那個方案的很大一部分原因。不是計畫。對方說無限，公平地說，他是在利用那個。然後變成遞迴的開發：他能更快改進正在做的東西，因為有這個適應性神經網路，可以最佳化特定的突觸元件。微型神經網路彼此相連、自我最佳化。傳統神經網路是單體，十億以上參數。他做的是非常窄、為一個任務明確建的網路：用某種方式交易這一檔股票，或理解某一個客戶區段。他在訓練 1 萬、也許 10 萬參數的模型，再套到應用上解那個問題。在那一件事上變得非常聰明。不用 GPU，因為模型遠小於那些十億參數的。字幕有一句聽成 subund。用那個 Rust 函式庫，幾秒就能做出只做一件事的神經網路，完全不用 GPU。範式從單體變成分布式的、許多小網路相連的突觸網路，彼此協作。他說這簡直是科幻。

## 示範在 GitHub 的 codespace，因為本機不該開那種權限

[44:10](https://www.youtube.com/watch?v=TT4iNHLEsRA&t=2650s) 他在做一個遊戲化的版本，讓人用挑戰來學，從早期使用者到他希望的 master agentic engineers。示範的是新專案 Flow Nexus，希望那週稍晚推出。畫面是 GitHub 裡的 codespace。跑 swarms 時記得是在 Claude 裡用 dangerously skip permissions。大概不要在本機跑。Windows 的 WSL、Mac 也許寬容一點。他這次跑的是 GitHub 上的 Ubuntu codespace。安裝用 npx 或 npm。npx 是遠端當下實例，永遠拿最新的。npm 全域安裝是一個時間點，不會自動更新。大家一般跑 npx。安裝是 claude-flow@alpha。Alpha 表示拿到他的 alpha，直到他有信心沒有 bug，或他停止開發。驗證是打 version。他當時跑的是 alpha 91。然後是 help。這是 CLI，他也說它是 MCP server，而且不是為了讓你直接用而最佳化的。這點有時讓人困惑。系統大多數能力是為系統自己用而最佳化的。例如更新記憶體，他可以自己打指令，但本來是要 AI 做的。他打了 session generate summary persistent。畫面說這個 session 已經跑了 9,700 分鐘、559 次編輯，是在給 context。要真的建東西，有 wizard，裡面有 training、verification，還有很多。字幕沒有把後面的畫面逐項摘完。

[53:55](https://www.youtube.com/watch?v=TT4iNHLEsRA&t=3235s) Simon 說自己在想 vibe specking：仍在 vibe，但比較少親手讀規格，而是跟 LLM 談規格，再從那裡生成。Reuven 說規格是過程裡最重要的部分。有人問他時間花在規格上，還是花在讓它跑。他所有時間都在規格上。讓它跑就是讓它跑。告訴它怎麼跑，是過程裡特別重要的部分。沒有像樣的 PRD 或技術規格，就不會有像樣的產出。Simon 問他現在是不是很 spec-centric，source of truth 是規格，生成之後還碰多少 code。他說看情況。做 AI-centric 的開發會有認知卸載。它在某些方面讓你變懶，他和別人沒有不同。改一個標題或某段文字，直接改比較快。即便如此，他仍傾向說 Claude 去做好了，這有點傻。他可以打開檔案，大約 5 秒改完。那個情況下 Claude Code 甚至更久。他就是懶。AI 讓你有力，也讓你在某些方面有點懶。

[56:05](https://www.youtube.com/watch?v=TT4iNHLEsRA&t=3365s) 下一步他認為會有更好的保真度。還在早期。他展示的是什麼可能、什麼做得到的領先指標。兩種看法。人看到他做的東西，叫它 AI slop，字幕聽成 sloth。不可能這個人這麼快做這麼多，還有真正的價值或能力。他認為幾天內平台有幾十萬使用者，大概說明不是那樣。但他理解為什麼人會這麼想。他們沒辦法審查，他也沒辦法有效審查幾百萬行 code。假設它很差，可以理解。真正的試紙不是好或壞，而是：它有沒有解決原本要解決的問題；其次，也許更主要的是，它有沒有以有效、安全、最佳化的方式做。能勾這幾項，就是全部要緊的事。它是不是有 50 年經驗的人逐行最佳化的工匠 code？不是。是不同的東西。他可以在片刻裡做出來說明，也可以做出一個問題的每一種可能、再選最好的。以前他得做一個假設然後走下去，對或錯都不能把每個假設都測過，一天沒有那麼多時間，成本也禁止。現在可以。他甚至不需要一隊人。只要對對的 swarm 問對的問題。

[58:18](https://www.youtube.com/watch?v=TT4iNHLEsRA&t=3498s) 現在最大的痛，他說是驗證。它是真的嗎、它有沒有用他要的方式做他需要的事。用 Claude Flow 的人，其實用任何這些系統的人，都在受這一點。不管是 Claude 還是別的，都有同一個問題。Simon 同意，這會一再聽到，而且對信任、對做出來的東西是否合用很重要。想再了解 Spark 或 Claude Flow，他終於做了一個落地頁，說自己像沒有鞋子的鞋匠。ruv.io 看他各個專案。GitHub 是 ruvnet，字幕聽成 githubet。專案從有用到瘋狂都有。他在推這些系統能做什麼的邊界。Simon 說也可以叫從有價值到令人啟發。Reuven 說，別人說不可能、說你瘋了，他就知道方向對。三年半前他們開始用 agentic engineering 這個詞，人人說那很蠢、沒有意義、聽起來像科學或醫療程序。那只讓他們想試更多。

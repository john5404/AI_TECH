## 一句話

Code 若是 AI 生成的，你更需要看得懂它在做什麼，因為那不是你的 code，你也不知道該往哪看。IDE 的導航和除錯因此更重要，不是更不重要。她對 AI 產生的簡短程式洞察的信任，和對 AI 產生的 code 的信任是同一件事：用你自己的判斷。模型很會說 you're absolutely right。

## 先能讀，才談得上信任

[0:34](https://www.youtube.com/watch?v=H2g4nFyqa8A&t=34s) 這是 Java Pro 和 AI Native Dev 在 JCON 2026 的現場。Marit 是 JetBrains 的 developer advocate。IntelliJ IDEA 今年 25 年。另一個她叫 Air 的東西還在積極開發，尚未一般可用。她不確定現在是 preview 還是什麼狀態，因為她在別的部門。字幕把那個 IDE 的另一個名字聽成 Agenda ID。

[2:20](https://www.youtube.com/watch?v=H2g4nFyqa8A&t=140s) 她在談找出真正的 bug，以及有時只是搞懂 code 在跑的時候到底做什麼：我讀 code 的理解和它實際做的是不是同一件事。尤其 code 是 AI 生成的時候，更容易理解它在做什麼變得更重要，因為那不是你的 code。自己的 code 你知道往哪走、看什麼。AI 生成的則不然。

[3:07](https://www.youtube.com/watch?v=H2g4nFyqa8A&t=187s) 它也傾向告訴你 you're absolutely right。也許它根本不知道那件事。所以更得確定自己懂它怎麼運作。一等的 IDE 正好幫你導航和除錯。後面有一段沒被摘到。

[6:07](https://www.youtube.com/watch?v=H2g4nFyqa8A&t=367s) 不管 code 是誰寫的，這些事仍然重要。你也不能再問同事「這是什麼意思」，因為沒有那個同事。

## 簡短洞察，以及叫它找自己的問題

[7:27](https://www.youtube.com/watch?v=H2g4nFyqa8A&t=447s) 它可以在你讀 code 時當場給洞察，例如一個方法在做什麼的短摘要。你自己寫 JavaDoc 仍然可以很長。這些洞察很短，她覺得很有幫助。就算 code 不是你寫的、你有一大堆要審，AI 也能幫。問題是信不信那些洞察。

[8:09](https://www.youtube.com/watch?v=H2g4nFyqa8A&t=489s) 到某個程度可以，但仍然要問：你信任那些 code 嗎？若不信任 AI 生成的洞察，你信任 AI 生成的 code 嗎？永遠用自己的判斷。也可以多模型：拿另一個模型來問這個模型寫的 code。它們會互相找出問題。她特別喜歡問：你剛寫了這段，找找你自己 code 的問題。它會說，對，有下面這些。它其實什麼都不知道。

[8:51](https://www.youtube.com/watch?v=H2g4nFyqa8A&t=531s) 在 Air 裡，她覺得他們有讓 agent 剛寫完的 code 被審查的選項。她只短暫碰過 Air。可以讓多個 agents 像隊友一樣互相審，虛擬隊友，但沒有電子雞可愛。它們很會同意你。You're absolutely right。

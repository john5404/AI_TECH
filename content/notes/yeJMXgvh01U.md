## 一句話

Flox 四年前開始時不是為了 AI。它要把軟體基礎設施底下那幾層收成一個指令，環境定義一次，任何 OS、任何架構都能跑，而且同一個輸入永遠得到同一個輸出。AI 把舊的 pattern 從一天一次加成一分鐘一次，任何一點不準就會乘開、變得不能用。Ron 的意見是：人和 agent 的產出愈確定、愈可信，AI 的 ROI 愈高。Container 擅長把方盒子運來運去。Flox 要的是盒子裡的東西不會從作業系統底下被換掉。

## Nix 的 purity，以及為什麼要貼著機器跑

[1:15](https://www.youtube.com/watch?v=yeJMXgvh01U&t=75s) Flox 今天是跨平台的環境管理員，開源。環境可以進 production、開發、建置和測試。定義一次，跑在任何 OS、任何架構。硬體、安全、AI、金融這些很複雜的地方都有人在用。底下是 Nix。Nix 是他心目中世界第六大的開源專案，每月超過一萬名活躍貢獻者。它是跨語言最大的套件庫，超過 15 萬個套件，也有自己的作業系統，但你不必換成那套 OS。Flox 的根是把 Nix 管理細環境的能力變得用得下去。Nix 有時像要讀一個博士才起得了頭，起得了頭就能做很驚人的事。

Flox 在乎三件事，想開放給更多工程師。第一，Nix 把歷史上幾乎任何軟體都看成同一種架構：依賴、函式庫、環境、agent 想拉或想跑的東西、甚至一個 LLM，都是一個 Nix package。那是環境，也是堆疊的一致性。第二是 build，可重現和確定性帶來 ROI。第三是軟體供應鏈安全，以及過程裡發生過什麼的追蹤。Guy 問這比較像套件的 alt text，還是比套件管理更低一層。Ron 說聽眾熟悉的是虛擬環境。把它想成虛擬環境砸進套件管理員，合在一起。不是更低，是同一層、不同的定義方式。社群內部叫 purity。任何衍生進 Nix package 的程式，必須自己帶上它遞迴依賴的一切，幾乎一直到 kernel。別的套件管理員不一定要求這個。你從 Nix 拉下來的東西，帶著建立、建置、執行所需的全部。這才有上游的可重現和確定性。

[6:25](https://www.youtube.com/watch?v=yeJMXgvh01U&t=385s) 大約四年前開始做 Flox，出自最大的量化基金之一，共同創辦人 Michael，有很重的科學背景。當時不是為 AI 規劃的。問題是：軟體基礎設施最底下那四層，為什麼不能收成一個指令，讓當時的人類開發者不用去想。Guy 覺得這很像他們說的 spec-centric。去年 AI 起來，大約是 ChatGPT 壽命的一半，浪潮來了。做 AI 的工程師要進自己的系統、要把 GPU 拉起來、要跟機器對得上。Flox 可以坐在本地、雲上或 container 裡。本地最重要，因為工程師碰得到、意識得到周圍的系統。環境知道 GPU、知道機器上的硬體。那是第一波。

和 container、VM、microVM 的差別是，Flox 完全在你的系統上本地跑。隔離靠檔案路徑，但它在系統裡面，沒有再抽一層。不必打洞告訴它去抓 GPU。AI 生態一開始就是要為了很多理由用這些 GPU。Guy 的對照是：想做可分享的環境給 AI 工程師，VM 或 container 離硬體太遠。Flox 給可攜，又真的跑在機器上。訓練模型、做推論，都需要那種靠近。最近六到 n 個月還有一波 local AI first，模型在本地拉起來。隔離發生在本地檔案系統，環境可以起、可以收，裡面有本地 LLM，對系統零衝突有百分之百的確定。Cursor 旁邊可以是 Windsurf，再旁邊五個模型，各自要幾百個依賴的不同版本。Flox 各自撐住，人和 agent 都不必在乎。Guy 說這是實驗的時代。人對工具不忠誠，同時開好幾個 IDE，不久前還是異端。他們對 VS Code 的忠誠，可能高過對 Cursor、Windsurf 或 Copilot。到這裡為止他講的都開源、免費。生意是另一回事。

## 一天一次變成一分鐘一次，誤差就乘開了

[13:50](https://www.youtube.com/watch?v=yeJMXgvh01U&t=830s) 他先聲明這是意見，從現在到兩週後 DeepSeek 5 出來，大概還會改 50 次。核心沒變：有東西在寫 code，有東西在部署，有人在用。意見是，無論產出來自人、agent，或兩者的混合，愈能讓它確定、愈可信，AI 的 ROI 愈高。他分成 human assist 和 human replace。不是那種邪惡的、工程師不必存在。是真的給他一個工程師、或讓他跑出價值，而不是在 AI 上面再疊一個新功能。對 agent 的世界，Flox 是基礎設施底下三階。你只說需要什麼，它做出來，完全可重現、隔離、沒有衝突，同樣輸入同樣輸出。也許本來十階的堆疊，前三階變穩了。第二件是 agent 可以在任何最新的東西上跑、測、部署。早上八點在某個 Linux 變體，晚上十點建議改去本地測，或十種硬體軟體組合。Flox 環境保持一致，agent 和其他人都不必改它。他還認為薪水最高的工程師會變成測試和 QA，現在還沒有名字：拿幾百萬行 code、用人去驗證。末端會有一個驗證階段。只要 Flox 環境是基線，別的東西可以把它拍上去就跑。可攜會是很大一塊。

Guy 聽到的隱喻是，AI 和 agent 把真實世界已經有的 pattern 增壓。以前可以靠人把環境同步、讓本機像 production、讓測試環境像上次做出來的東西。從一天一次變成一分鐘一次，任何百分比的偏差都會乘開，變得不能用。Ron 幾天前為了試水又做了一個 app。簡單的話，用 spec 或英文定義，它就去建，資料庫產品也接上。他只需要做認證和連線。然後他想拿走、在上面繼續蓋。從 agent 交回人，沒有他希望的那麼容易。以前的浪潮看過：雲到本地，一個工程團隊到另一個，分散的團隊也一樣。以後也會是 agent 到 agent。

Guy 把信任收成一桶：環境設錯會出一整類問題。另一個宇宙裡，agent 每次自己編環境、寫一串指令。它每次不會做得一樣。能不能把那件事做成確定的。可攜和可重現是為了不要 works on my machine，好交接，人或 agent 之間都一樣。Ron 的五年想像是，code 會換手，就像開發者換公司、換團隊。今年人在編輯器之間跳。他完全想像得到，今年用一個 agent 平台，明年最聰明的是另一個，也許因為他更願意付費，或生態變了。他要那個系統能立刻進到他的 code，就像資深工程師換進團隊。那才是他看到的 AI native。

## 方盒子很好運，盒子裡的作業系統會動

[22:25](https://www.youtube.com/watch?v=yeJMXgvh01U&t=1345s) Guy 問，為什麼不預設用 container 當共享環境。Ron 說為什麼不能兩個都要。Container 解決的是運輸和編排。Amazon 倉庫裡東西進箱子，箱子是方的，方的東西好運，人喜歡方形。較重的差別是你怎麼定義那個 container，以及什麼東西可以在你腳下移動、把可重現和確定性拿走。Container 的最佳實務通常沒有那麼好。就算你定義得再好，作業系統上仍有層會從底下移動。沒有東西百分之百可重現，但這會讓它明顯更不可重現。在他看來，當世界被增壓到 code 是 10 倍、20 倍、100 倍，這就有差。用 Flox 定義那個 container 幾乎免費，然後再跑 container、走你的流程。兩件事發生。一，你想離開 container 做開發時，編排他仍覺得 container 很強，但開發環境有一個共同基線，可以回本地、去最新的東西、給喜歡 container 的 agent，也給不喜歡的。你對它變得無關。二，基層有一份 spec 式的定義，會跟著時間一起長，放在口袋裡，想拿出來就拿。今天 Flox 和 container 是一起走的。若開發時還得在 container 上打洞，把東西放進盒子的意義就少了。本地、必須意識到系統的、比較複雜的，用 Flox。要送出去時再扔進 container。用 Flox 和 Nix 送出去也可以，百分之百，但今天不必。

Guy 說他不知道 spec-centric 有沒有唯一正確做法，但和宣告式很合拍。Container 是環境的一種實作，不是你想達成的那層更高的抽象。再高一層就更可攜、更能適應。今天很多情況生成出來的會是某種 context。更早 Ron 講過靠近硬體：工具要直接碰到 GPU，container 也許給得了、也許給不了，你有選擇。AI 乘上的不只是動作的頻率，還有每一下有多快，工具的 overhead 就出來了。Tessl 用很多方式生 code，也想用版控追這些變更。他們覺得 git 對這種用法是減速，團隊自己寫了一個叫 notgit 的服務，字幕聽成 notg。它不是 git，感覺有一點像，快、在本地，功能遠沒有 git 完整，但循環多得多。Container 起落的速度、沒有它時的執行速度，在某些情況下會有差。那大概是邊緣，不是常態。

[28:27](https://www.youtube.com/watch?v=yeJMXgvh01U&t=1707s) Ron 同意。Cloud native 對很多人意思不同，現在仍是。他們剛在一份採購表上被問是不是 cloud native。對他來說，AI native 和其他 native 的差別就是變更和迭代的速度。他有偏見：腳下是實地而不是流沙，總是淨好處。基礎設施最底下幾階更穩，你對那個速度就更有韌性。AI native 不是搬去某個雲，是另一個星系。

他們稍微跳過一件核心的事：agent 一開始就需要環境，因為生出來的 code 得面對現實，要跑，或拿到基於執行的回饋。最常見的就是：我寫了 code，需要一個地方跑，看它到底能不能用。在測試、驗證、build。Nix 二十年前做的一件事是重定義 SDLC。它說不要從開發者環境和開發開始。若從 build 開始並把它定義好，其他東西免費得到。這碰巧和 agent 對上：agent 第一次真正在乎這個生態，是它要 build 那段 code、測它、看例外、看 bug 的時候。他過去一兩年看到巨大的成長，而且還在指數變大。環境要瘦、要跑得快、要可攜。

## Minute app 很好玩，五年後堆疊會拆開

[31:22](https://www.youtube.com/watch?v=yeJMXgvh01U&t=1882s) Guy 把環境分成幾域。一是 runtime，剛談很多。二是生成一個環境。三是挑選環境，或把它當工具用。也許還有第四，隨時間學習。Vibe coding 工具要給一個somewhere 跑得起來的輸出，所以得生成環境。Ron 說這是較新的，過去一兩個月才起來。他的假設來自週末邊看 Bosch Legacy 邊做 app。很多 vibe coding 產品在把 time to market 拉到最大，還沒想交接、永續的 code、長期高影響的產品。他們想的是怎麼發布。這週稍早一頓晚餐，Dana 說她在演唱會排隊時做了一個 bingo app，因為朋友想玩。那正是 vibe coding 的用途。它們還優化成讓你在它們的網站上自己部署，之後人要做的互動盡量少。那就省掉長期思考：我要設什麼環境，六個月後有沒有人會做這個。他叫這些 minute apps。過去幾個月，這些產品開始想怎麼多變現、怎麼讓客戶黏住。進來的對話多到讓 Flox 也在想：在 AI native 的世界當基礎設施最底一階是什麼意思。他們有資料，哪些套件和依賴最好、最快、最安全。那是在看 AI 環境生成的未來。

Guy 喜歡 minute app 這個詞，聽過 disposable apps。他老想食物：這東西你會端上桌嗎，大概不會。若你在家、餓了，這就是你有的。短期內它們也受益於現成環境，從架子上拿一個來跑。很多其實不太在乎多樣性，選一個很特定的 Supabase 和一套設定，環境是挑死的。等到想回購、想長期，可攜就出來了。開源的，例如 OpenHands，字幕聽成 all hands，也許生成更可攜的環境格式，想在哪種基礎設施跑就跑。SaaS 則可能偏成我從頭到尾幫你處理。標準的好處是你可以把它拉起來繼續。也允許工具鏈：不必同一個工具既最會生 code、又最會部署、又最會操作。另一個工具可以用同一種語言談那個已經部署的東西，然後接下去。

[36:01](https://www.youtube.com/watch?v=yeJMXgvh01U&t=2161s) Ron 對五年後的強意見是，會不會有一個 AI Skynet 什麼都做，還在下午給我們宵禁。希望不會。會有產品、公司和 agent 專精自己的區域，生態會重建。你們在做的 AI stack 會慢慢收成 AI native stack：流程的每一段用什麼。基礎設施地圖和 SDLC 也許完全不同，也許不是 code、build、deploy，也許很著重測試。也許不是大公司裡十二個團隊，也許只有三個。他認為永遠會有交接，因為一個 agent、一間公司不會把每件事都做得最好。Guy 也常想工具的正確範圍。兩條軌跡。一是一顆大的大腦平台，什麼都得知道，超級智能的 Skynet，我們依賴它做一切，它不做我們就卡住，或變成那個平台的 power user。他覺得有點悲傷，因為限制創新，拼圖裡有好點子的人進不去。另一條是工具鏈，不同元件可以混進來。Netlify 的 CEO 兼 co-founder Matt Biilmann 上過節目，字幕聽成 Matt Bilman、Netifi。他對 web manifesto 和開放生態很熱。封閉花園很誘人，因為他們一直在說的隨機性和非決定性很煩人，變數少一點，有時更快做出能用的東西。開發生態想要的是開放系統，一段旅程上最好的工具，交得出去。開放的環境定義他很喜歡。環境常常被忽略，對平台和維運的人卻很關鍵，很多開發者不太想它們。所以他想投資可攜、開放、基於標準的 agent 輸出。Ron 說他顯然不會反對。就算沒有不同公司，每個專精，最好的測試 agent、或高通量生技、蛋白質合成，都會有開源對等物。就算有 AI Skynet，也會有開源的 AI Skynet。誰擁有閉源的那個，決定哪一個比較可怕。人要能在兩者之間走，才走得更遠。

## 先說你要做什麼，不必先說 Python 3.12

[41:02](https://www.youtube.com/watch?v=yeJMXgvh01U&t=2462s) 第三段是環境當作人會用的工具。人會慢慢知道該用哪些工具，包括一些 SaaS、一些上面還堆了東西的 container。他們花很多時間把 OS 上面那第一階基礎設施做穩，也因此看到很多資料：什麼叫最好的環境、怎麼建、什麼跑得更快、更可重現、更確定。下一步是，人、agent、或人吩咐的 agent，只要告訴或秀出想做什麼。不必說要 Python 3.12，或某個資料庫的某個版本。就像你剛剛吩咐 agent 那樣。Agent 也許再翻成基礎設施那一層的話。Flox 輸出那個 agent 需要的東西，環境這層軟體織物當基線。幾年後，人和 agent 可以用英文，或任何語言，對整份底下的基礎設施說想做什麼。他最後做的例子是給家人的投票 app，動態的，每個人看得到別人的票。Agent 翻譯，Flox 看那段 code 或那句英文，自動知道要拉什麼進來給 agent 用。雙向：agent 說我在建這個，Flox 自動生成；若有 agent 想優化，Flox 也可以建議理想環境，agent 再依使用者和 spec 往上建。幾年後會完全走到那裡，而且會被優化完。

Guy 說今天用 AI、做 vibe coding 的人不會立刻碰到這個痛，因為做平台的人已經選了一組很有限、很小心的環境，然後只部署在那裡面。開放的 web、部署在 Netlify、一個 React 應用，都是很特定的，也只生成到那個範圍裡。痛是未來式。Ron 用軟體工程師的職涯看：這麼專、這麼窄，職缺今天還要求某種語言五到十年，因為你知道哪些套件最好，你帶著那個世界觀來。以後只要把最好的需求定義出來，空間可以放大 5 倍、10 倍，甚至 100 倍。現在這些 app 做得出 minute apps。以後要做得出 100 個 minute apps、10 年的 app，希望還有 100 年的 app。

Guy 從另一個鏡頭看，今天人最在意的是環境讓 agent 做得到事：幫我生 code，為了生 code 它需要一個環境來跑工具、跑測試。輸出想得比較少，因為在封閉花園裡生成。宣告式也想得比較少，因為生出特定的 code 已經很難，本來就要把 LLM 的範圍收窄。Vibe coding 和任何長期能活的應用之間還有很多缺口，沒有人想維護，也沒有人想環境裡的東西需要更新時怎麼辦。那是眼前問題再往下七步，或他說的七十個問題。可是你一想軟體要活得久，它們又很根本。Ron 說今天的 agent 優化的就是 minute app：盡量簡單、盡量便宜。使用者要一個挺基本的東西，用最少的 bug 吐出來。從提供 Flox 和 Nix 的假想夥伴來看，這個優化讓他們非常在乎把環境拉起來、測到那個 minute app 完全煮好、然後送出去。環境只是交易過程中的一塊。過去幾個月他看到很多人開始想，這些 minute app 正在變得可互換。太多產品都能做全家看得到彼此投票的 app，接上很棒的 Supabase。錢在哪，ROI 在哪，差異在哪。ROI 不在 minute apps。他們開始說需要基線，使用者要能把東西匯出，然後像和這個 agent 坐在同一隊那樣輕易接著做。那就是他前面說的，從 human assist，到讓人舒服，再到真正的 human replace，好讓人去做更大、更有創新的任務。Agent 變成隊員，而不是那個被叫去拼一個三週後就忘掉的辦公室訂午餐 app 的實習生。你不會一直雇一個只做得出三天或三個月壽命應用的初階開發者。Minute app 和能延伸進大生態的，目標市場和市值會很不一樣。兩人都不想貶低今天的應用。它們讓人碰到魔法，感覺很神奇，也是必經的迭代，不能直接跳到終點。有趣的是中間的缺口。

## MCP 是把開山刀交給亂數產生器

[50:38](https://www.youtube.com/watch?v=yeJMXgvh01U&t=3038s) Guy 還有一個環境問題，然後想聽那頓晚餐。MCP 現在很紅。Flox Hub 放著一大堆別人做好的環境。從外行看，很想在上面蓋一個 MCP。Ron 的行銷主管 Ross 有句話黏住他：MCP 像把一把非常利的開山刀交給一個亂數產生器，像給 HAL 9000 手和腳。字幕聽成 HAL 9,000。Flox 當然在看 MCP。他覺得那是他們在做的事的更有能力版本。AI 忽然有手有腳，agent 可以出去接 email、回銀行、檢查小費有沒有被坑、碰到銀行。MCP 會跑軟體。那份軟體必須事先、可靠地提供，和其他東西一樣，或者讓 agent 能動態擴。可靠性再升一階。若你賣的 agent 接了一堆真實世界的外部服務，卻沒有那份 AI 的信任和可靠，你就是把一個更危險的、拿著開山刀的亂數產生器，掛著你的名字放出去。Guy 聽懂了，也覺得 Ron 一直在指自由度、有多少東西會變。MCP 像一個沒有結構的 API，也許能用、也許不能。今天它發亮的地方仍是有人看著的流程：你給它工具，若它砍掉一條腿，你在說 yes 之前至少看得到。Guy 很喜歡 MCP 的 resources，不只是 tool call。讓不同的 LLM 知道、而且常常成功地從 Flox 拉下某個環境，走向那種宣告式。他們接過不同東西，也和一些夥伴在實驗。自由度正是留給創意的空間。他賭接下來一年它會變得嚴格很多，或至少有一個可以變嚴格的選項。

[54:16](https://www.youtube.com/watch?v=yeJMXgvh01U&t=3256s) 晚餐是和一些頂尖科技領導人，有人在 AI 上建造，有人在做 AI 的地基。他不點名。三件卡在他心上。第一，AI 對開發者生產力的影響仍然很難量化、很難據此做決定。沒有人驚訝。AI 之前就很難量化：inner loop、outer loop、行數，行數完全是瞎的。這讓他好過一點，因為他會想是不是大家都在用 AI、看到巨大且可量化的移動、而且很有策略。一般來說很多人仍在跟這件事搏鬥。AI 又是那個大乘數：我們一直想要開發者生產力的度量，現在也許有夠多的動機去追。他好奇何時會開始談 agent 的生產力。他看過一些人開始談，不多說。

第二是他們整集滴到的那層玻璃天花板：怎麼把創新放在 AI 的信任上，而不是放在讓 AI 多做一件、或做得更好。晚餐上全是食物的比喻。他想要 AI 當終極的副主廚。不要它做完一餐、等他忙完再來檢查。他不需要米其林。他要它很一致地把麵包切開、放上桌，他就可以去做別的。很多人仍感覺到的問題是，最好的模型和供應者，五次裡有三次、甚至四次，麵包切好了、放上桌了。第五次或第四次，桌上放的是石頭，或橄欖油換成機油。那就沒辦法完全離開 AI 做得到的那區，去花更多時間在別處。Guy 問，要改進的是 AI 變得更確定，還是人改變工作方式、去對付機率。Ron 說兩者。他確實想要 AI 更可重複。叫它切麵包放上桌，他想要大約 95。人也會錯。昨天他的雞帶了奶油，他不想要奶油，他們回廚房，他相信沒有 AI，地點字幕聽成 centro。有一個門檻，還沒定義，大概心理成分多過別的。另一段對話是，要不要把標準放低一點，因為標準是對著做這些事至少三三十年的人。回一封信確認時間，他不在乎少一個句號，或語氣誇張得不像人。也許信尾寫 run by Ron's AI，社會就接受這不是 Ron 在說 good sir、謝謝、我很興奮、接受你下午一點的正式邀請。那樣就省了時間。所以是兩面：心理預期的移動，以及 AI 變得更可重複。Guy 說這在軟體開發特別妙，因為我們基本上期待軟體是確定的。有經驗的人知道不是，因為環境、因為資料。但確定性的門檻很高，AI 系統現在沒達到。有些程度我們得接受，同時它們也得走到那裡。晚餐上還接到另一段：也許 minute apps 就是新標準，也許一半的東西變成拋棄式杯子。不想污染地球。但也許某些產業會標準化拋棄式軟體，每幾個月或每幾週帶著新功能送出去，沒有人知道怎麼重現，而那完全沒問題。那是標準問題，也是人的心理問題。

第三件他沒預期，一說出來就發現自己想了一陣子：新創和科技公司裡的職涯。我們在離開那條明顯的路。小公司和巨型企業很不一樣。現在有一條明顯的職涯，思考得改。怎麼激勵自己、激勵團隊、讓他們看見成長。離開的是：你做更多、你雇更多人、你當 manager、再當 manager 的 manager，範圍和影響力一條線對上去。AI native 的角色裡，那條對應是什麼。也許不再需要中階管理。也許一個人可以有非常多的下屬，字幕那個數字沒有聽清。當成長不再明顯，怎麼激勵個人、怎麼給一條路。

[1:00:58](https://www.youtube.com/watch?v=yeJMXgvh01U&t=3658s) Guy 問，若有一個 15 歲的孩子，現在還要不要去大學讀 computer science。Ron 說他很有偏見，hell yes。除了偏見，基本功不會變。過去五十年任何一波軟體，基本功都在。它們變大了、變好了，但還在。他現在給的建議是 T 型。不管選哪個產業，既然問的是軟體，就去讀軟體工程，但要真的深，深到基本功。他不在乎你選 Python 是因為喜歡蛇，或為了某個怪理由選 C。深到：軟體為什麼這樣做、怎麼做。然後再往上。那永遠會在。我們只是再加一層，從高階語言，到現在用英文寫 code。仍然有人或有東西在碰基本功。懂它們，不管抽象到哪一層，你都會是用那層抽象最有效的人。所以軟體工程是 yes，而且不管是不是軟體，都是 T 型。

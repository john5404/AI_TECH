# Vibe Coding SimCity II: Injecting Chaos with Natural Disasters and AI Tools

這是 AI Native Dev 的第二集。上週 Macey 出題，要 Simon Maple 和 Joe 各做一個小鎮模擬。Simon 用 Base44，Joe 用 Bolt.new。這集他們交換成品：Simon 拿 Joe 的 Bolt 程式，用 Cursor 改；Joe 拿 Simon 的 Base44 程式，用 Windsurf 改。要加什麼，開錄才由 Macey 給。片長約 60 分鐘，英文自動字幕。贊助名稱被聽成 Tesla。畫面很多，他們說會把做了什麼講出來。這份筆記依英文原稿整理，專有名詞保持英文。

- 原片：[YouTube](https://www.youtube.com/watch?v=dzXGY8YUx-8)

## 一句話

任務是至少兩種天災。Simon 在 Cursor 裡改得很快，diffs 也看得懂，但 Joe 的程式本來就滿是事件和 bug，天災自己消失、沒有警察局也能破案，他覺得自己失敗了。Joe 在沒用過的 Windsurf 裡先做出地震，動畫真的嚇到人，房子會消失；中間模型困在自己剛寫的 diff 和一堆它沒引入的 lint，他用兩秒手動改了函式順序。原型工具能很快交出能點的小鎮，編輯器要在別人的不穩程式上加功能，就容易進入「我做好了」但其實沒好的迴圈。

## 兩座很像的鎮，一句話才揭曉要加天災

[0:51](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=51s) 不必先看上一集。螢幕分享很多，只聽 podcast 的人他們會敘述哪些成了、哪些卡住。YouTube 看得到工具在做什麼。Joe 在頁尾加了 copyright。Simon 覺得兩人的成品意外地像：幸福、人口、住宅。他問 Joe 第一句 prompt 是不是只寫了五個字。Joe 說沒有，寫得更多。即便如此，輸出仍很像。Joe 的鎮有居民，沒有路，也沒有產業。人住在那裡，然後發生警察、火災或醫院事件。還有社區中心，Simon 笑說那是大家可以一起出狀況的地方。

[3:46](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=226s) Macey 遞信封。兩邊要做同一個修改：加上至少兩種天災。Simon 覺得以 Cursor 來說合理、也好加。Joe 用 Windsurf。他的直覺是這種改動在 Base44 裡會更容易。Joe 的鎮卻很適合天災，因為它很悲觀，醫院、消防局、警察局都有。

[4:29](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=269s) Simon 先摸 UI。他缺錢，能蓋兩棟房子、一間醫院、一座消防局，一般設施不夠。他說這讓他想起自己來的地方，字幕聽成 Beijing steak，後來又變成 Beijing Stoke，不另考證。他可以一直把日子往前推。錢從哪來、誰在農場工作，他沒有答案。他不確定有沒有會留住的狀態，覺得每次都得重做。

## Cursor 看得到 diff，卻蓋在不穩的地基上

[5:12](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=312s) 他猶豫要不要先看程式怎麼組織。畫面上是棋盤、格子、遊戲控制、把日子往前推。他覺得意外地好懂，也許因為和他自己的很像，也因為他用 Bolt 做過很多遊戲，結構是他預期的：遊戲棋盤、控制、事件系統。那個事件不是天災，只是棋盤上發生某件事。他期待 Cursor 的速度，和 Base44 完全不同。第一句是把起始預算改成 15,000，然後自己改成 25,000。Cursor 順便列出東西的價錢，他說這是很相關的 context。他再叫它用預設的五棟房子加上其他每種建築各一棟當開局，接著改成隨機，好讓每次稍微不同。它只在第一次隨機。人口被設成 100。他接受改動，看到「歡迎來到 Tiny Town」和一座起始鎮。它相當懂他要什麼，但沒有完全對。

[7:54](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=474s) 他喜歡這裡的原因，正是他討厭 Bolt 的一點。Bolt 的檔案到四五百、六百行時，改一兩行也要把整檔重寫，慢，而且他不知道改了什麼。Base44 他甚至沒看過程式，假設也一樣。Cursor 的 diff 他看得懂，可以接受。重開之後，社區中心有一場音樂活動被當成緊急事件，地點字幕說是 34，他說那是從零開始數，所以是第四、第五格。它在閃。他不知道除了買票還能怎麼反應。結果是一場很大的成功。他不確定警察或消防有沒有參與。鎮沒有重設。他說自己不是很會 JavaScript 的人，預覽和 `npm run` 也不確定。他是 Java 開發者，覺得這像 Maven 的 clean、build、install。他按了兩次。

[9:34](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=574s) 他想的是 SimCity，先提到外星人攻擊，然後改走純天災：洪水或火災。起始鎮沒有被加進他要的東西。他改口說隨機發生，平均每十天一次，再改成五天，免得等太久。Joe 說這是一座恐怖小鎮。Cursor 要做一套隨機天災，改 `advance day` 裡的 chaos manager。它自己訂了 20% 的機率：嚴重度 8 的野火、7 的健康緊急、犯罪潮。每場隨機分到一棟建築，影響幸福和安全，並說這會增加挑戰和不可預測。Simon 覺得它應該蔓延。Joe 補：火災蔓延，房子該消失；犯罪潮也許只是不給你收入。後果要有。Simon 先求簡單，做出來並蔓延，再做衝擊和解決。他問這算不算專業，又說自己多年前是寫 code 的人。

[11:56](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=716s) 他愛的是速度。他分兩種 AI 工具。一種做很多，你更在意整體準不準，因為你不太看 code。這裡他要 review，所以速度要緊。它把最近的建築和相鄰建築分開，他覺得多餘：相鄰的本來就是最近的。他拿掉相鄰，只留最近，然後重建。緊急事件會自己解決，字幕說謝謝附近的醫院。也有疾病發生在沒有建築的地方。火災時 Joe 提醒他沒有消防局。回應是火被控制住了，但反應慢，後果不大。他一次下了三件事：天災只能發生在已有的建築上，空地不行；不能自動解決，使用者必須做一個動作；相關的復原服務必須在場，例如火災要地圖上有消防局。Joe 問，火災當下沒有消防局，能不能現蓋。Simon 說那就等六個月把消防局蓋好再滅火。Joe 說這很像 LLM 的邏輯。Simon 承認現實裡他會一次改一件並確認，但只剩三四分鐘，所以一次全下，而且盲目接受。

[15:40](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=940s) Joe 說，做真正的軟體時，決定要改什麼、怎麼改，才是工作的大頭。Simon 叫它預設幫他加建築，它沒做，他仍在手動加。一棟住宅「準備好派對」，四個人。犯罪潮打在兩棟建築上。他不能進入下一天，必須回應。它解決了。他沒有警察局，卻能解決犯罪。他再要求：沒有警察局不該能解決犯罪；天災進行中也要能進入下一天；一次只從一棟建築開始，因為跨兩棟讓他煩。改完仍不能進入下一天。他覺得很挫折。過去的經驗是同一件事要講很多次，到某個點就停住，跨工具都這樣。它還說最近建築的函式不再需要，但他認為絕對還需要。若認真做，他會把改動切更小，並驗證。他的直覺是，若叫 Bolt 或 Base44 做這些，可能更成功。他覺得這一輪自己失敗了。

[19:05](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=1145s) Macey 說他做得可以。有些改動有意思。想像四年前把這技術給人看。人們現在不想談的是：他沒碰任何 code，拿了另一個工具的原型，看懂、除錯、做了相當根本的修改。Simon 的信心卻掉了。開場覺得哇，這真的能動；現在覺得沒有一樣是真的在動。他想先做一份品質計畫，確認每個元件在做該做的事，因為他在不穩的東西上往上蓋。也許不該怪 Cursor。問題是底座，也就是這份起始程式。他笑說這完全是他對 Joe 的預期：滿是 bug，設計不當。他把元件補穩，Cursor 才更有機會做好。他仍喜歡這種互動，挫折是那個迴圈：叫它做，它說做好了，你跑到錯的環境，發現還是沒做。

## Windsurf 先把地震做出來，再和自己的 diff 吵架

[21:10](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=1270s) Joe 把 Simon 的專案跑起來時發現，Base44 好像把自己當成資料庫。認證怎麼接，他們沒弄懂。系統很封閉，很難在不登入 Base44 的情況下在本地跑。它想把你送回他們的 app，這就失去本地工作的意義。送回去又報錯，Joe 猜是認證從本地副本發出，對方伺服器不收。他們在 Base44 裡下 prompt，試著把它從自己身上拆開、拿掉認證。目前看起來成功，也可能他們做錯了。

[22:08](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=1328s) 他把鎮命名為 Joe Town。他不知道 Simon 怎麼下 prompt，但元素很像。treasury 這個詞他自己的 prompt 沒用過，這裡也出現了。幸福計、格子佈局都很像。日子會自動往前走。Simon 有路，每樣東西有屬性：有的讓人更幸福，有的要花錢。Joe 自己的鎮若能動，錢只會增加，沒有成本，所以 Simon 這座也許更現實。格子數量好像也一樣。Prompt 寫得不夠具體時，工具會填同一批空隙，而且跨工具也常填成一樣。信封還是：至少兩種天災。Macey 說 Simon 佔了便宜，因為 Joe 本來就有事件的概念；另一方面，程式的狀態不同。Simon 的鎮有醫院，沒有消防局。天災大概會打幸福和金庫，也許還有人口。Joe 先想健康爆發，會隨時間自己過去；再想地震拆掉一些建築。

[24:42](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=1482s) 他沒用過 Windsurf，常用 Cursor，所以看起來熟。他不看 code。他先寫一段簡介：這是小鎮模擬，維持金庫和幸福，使用者放建築，日子推進會影響這些數字。也許不必解釋，它讀得懂 code，但中間可能隔了一層，所以他想稍微帶路。天災在隨機間隔發生，頻率要容易調。先只有一種：地震打到格子的一個子集，裡面的建築被毀，隔天消失。他預期會有毀壞狀態，隔天清掉，才能蓋新的。幸福該下降。人口也該下降，因為建築裡有五個人或二十個人，也許不是都在家。金庫他不預期會動，除非清運要錢；房子的錢已經花了，房子沒了。模型過了那些安全閘，先去讀檔。看得到思考過程讓他比較有信心，但對他沒有幫助。然後它把他的話複述一遍。他甚至沒發現它還在做。新檔叫 `naturaldisasters.js`，他覺得檔名很好。地震頻率是每天 10%，他說現實裡很可怕，像回到舊金山。有一層迴圈包著另一層。Diff 讓他糊塗，看起來像把檔案頂部的 import 重寫了，很難看。他決定盲目全部接受，因為他很有信心。匯入時 lint 錯誤多到惡夢，他先忽略。它還在迴圈裡：做地震的視覺、修問題、修 lint。他看到的 diff 可能已經過期。人被叫進來，因為需要 human in the loop，但它還沒準備好，他什麼都不能做。這是去泡茶的時間。若它花十分鐘把 code 變漂亮，他可以接受。他想對快速原型說：別那麼在意 lint，先讓東西動。它像一個很想表現的初級工程師。

[29:27](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=1767s) 它說做完了，而且很有信心。每天結束有 10% 機率地震，隨機區域是兩到四格，有搖晃的紅色疊加，頻率和大小可調。日子是自動走的，看起來不太像在動。他重開伺服器。影響比預期大。它加了地震動畫，他很想看到。依賴沒變，package lock 只是因為他裝過 npm。沒有明顯錯誤，然後前端說不能在初始化之前使用 `handleEndDay`，檔案是 `simulator.jsx`。他進入除錯。有些改動要按接受，有些好像已經接受。聊天上方說零個檔案有變更，工作區裡卻有很多 diff，還有一個新檔。他覺得這些編輯器在 Git 之上又多了一層建議中的工作複本。他的理解是接受之後才進工作複本、再 commit。這裡的內部狀態管得不好。修法看起來合理，但他警惕它還改了好多別的。它先說這就是原因、我來修，又說噢我看到問題了。是兩個問題，還是修了兩次，他分不清。意識流很亂，而且自己決定做沒被要求的改動。他想把每次改動的範圍縮小。不行的話就重來，先寫處理一部分的檔，再疊 UI。那是他在遷就 LLM。Macey 說他沒有要求很過分的事，不是五件事的清單，只是加上這個概念。他們在工作上看過，規定得太死，效果會反過來，程式會變差。他給的是開放的，它卻很掙扎。這種能改多檔、一次握住很多 context 的流程，除非他對設計很有意見，否則不該還要他把問題拆開。也許是問題太多，它被絆住。

[34:24](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=2064s) 他刪掉 ESLint 設定，希望編輯器知道他不在乎 lint，並取消那個混亂的迴圈，開一場新對話。Base44 生出一份相當完整的 ESLint，生出的 code 卻完全不合規。封閉環境裡他們也許不受這個苦，可能是留下的產物，也可能他們認為這對保持乾淨有好處。只有真的照那樣寫 code，才有好處。新對話又進迴圈：`handleEndDay` 宣告了兩次。他懷疑它找到錯、修好，再分析自己的 diff，於是看到兩份宣告，因為那份就是它剛寫的。它在氣自己的 diff。他改手動修。函式在下面才定義，呼叫卻在上面。他把 `handleEndDay` 挪到這組函式的第一個。`handleDeleteBuilding` 也一樣，順序錯了，是很基本的事。可能又引入別的 bug。畫面回來了。他自己修只用了大約兩秒，他本來想讓模型修。他說這很值得記。

## 第二種天災是閃電，信任已經很脆

[37:01](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=2221s) 現在預期每天 10% 地震。他先調到 70%，再 80%，好測試。Simon 看到他直接改 code，因為已經不太信任聊天。它說過有搖晃動畫。他把房子排成能接到地震的樣子，像海戰棋，錢也花光。再改成 100%。註解的自動完成很快。日子結束時某處該地震。動畫其實不錯，它們很會生 CSS 動畫，而且嚇到他了，這算成功。它打到一塊他以為沒有建築的地方，也可能房子立刻消失了他沒看到。幸福只掉了 1%，也許本來就會隨時間下降。房子確實消失了。若挑剔，他預期它先壞一天再消失，沒有那個毀壞狀態，但不要緊。錢沒掉，清運成本可以之後再加，否則他現在該破產。人口應是 40，所以地震沒有殺人，人只是沒房子。他沒有要求一場會殺人的地震，這樣算公平。幸福又掉，不確定是不是只因為過了一天。金庫數字沒被直接打到，進帳速度變慢，是因為這些建築每天賺錢。

[40:19](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=2419s) 任務要至少兩種，他只有地震。兩分鐘內能加什麼。Macey 建議閃電：打單格，像海戰棋，看它會做出什麼新設計。Joe 先 commit，還是 conventional commit。新對話：閃電打一格，有建築就毀，幸福下降，毀了建築掉得更多，數字讓它自己定；動畫要像地震那樣酷；頻率可設定。他想讓它在一天之中發生，而不只在一天結束，但這時不想再加。信任已經很脆。他會盯著，因為上次它把事情搞亂，而且很久。它去看自己剛寫的天災實作，但這是新對話。Context 怎麼管，他覺得很有意思。元件變得又大又複雜，它把自己搞糊的機會很高。它把東西做得更通用，動畫是淡入淡出，這次沒上次那麼亂，因為鷹架已經在了。他盲目接受。接受也許什麼都不做，只是告訴 Windsurf 他滿意；拒絕才會還原。變更已經在工作複本裡，接受不是 commit。沒有錯誤。他把閃電調成 100%。又少了一些建築。日子的速度是個魔術數字，多處都是 60，他討厭模型這樣寫。地震先發生了，他開新對話把地震機率降到 0，它立刻懂了。他覺得上次是因為要求太複雜。Windsurf 有沒有特別宣傳自己較擅長小改、不擅長大改，他不確定。他說 Cursor 相當會做大改，但那不是他日常的做法。日常是在熟悉的程式庫裡把問題拆小。這裡沒有測試、沒有評分標準。

[45:12](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=2712s) 閃電出現了，看起來打了兩格。動畫酷。也許邏輯是一格，視覺大小錯了，他們很難測。錢只夠再蓋兩棟房子。他在 code 裡看到這像是 local storage，就給自己加了很多錢，然後開始花。電廠在邏輯上佔四格，畫面上只佔一格。他喜歡建築可以佔更大空間。公園也許該例外，閃電不該毀掉整座公園，除非照他那種比較狠的風格來。幸福很差，是因為電廠。每晚都有閃電。一個月裡有五十次地震。這座鎮很辛苦。幸福到零，支持率 0%，他覺得公平，因為大多是電廠，加上一棟可憐的房子、兩棟房子。七十個人住在這裡，兩棟公寓和一棟房子不夠住。他的意見是，這不是你想住的鎮。Macey 說他做到了兩種天災，中間有一堆折騰，但做成了。

## 原型很快，接下去就進迴圈；沒人先問程式是什麼

[47:14](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=2834s) 成品 Macey 覺得很像，路徑很不一樣，而且每人用了兩個對自己新的工具。Simon 喜歡 Base44。他是 Bolt 使用者，看到很多相似。Base44 把他帶到想要的東西快得多。看 Joe 把他的 code 和那些依賴弄進 Base44，其實很挫折。原型階段他玩得很開心。Joe 覺得從很短的 brief 到一個有用、設計不錯的 app，從零到一很驚人。它像 IDE，又少了很多 IDE 的功能，有點恐怖谷。他會去按 command-click，但沒有用。他自認比較像 power user。下次朋友或家人說幫我做一個 app，這東西用得上。可丟棄的 app、可丟棄的 code，很適合。

[48:40](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=2920s) Windsurf 和 Cursor 的概念很像。側欄那個聊天大家都在取好玩的名字，互動模型很接近。Joe 這次的用法不是他日常用 Cursor 的方式。日常他會想清楚、把問題拆開、把改動收在局部。這裡他不認識程式庫，也不想認識，只要它實現一整個大功能，所以難比。他搞不清變更的狀態：什麼時候真的在改磁碟上的檔，什麼時候只是建議。他覺得 Cursor 也有這個問題。問題一大、時間一長就更嚴重。他不能同時重構別的東西，否則 commit 歷史會變成惡夢。Simon 身為 Cursor 使用者，這次沒學到新東西。他覺得很難再往上蓋。每次都是那個令人挫折的迴圈：他要一個改動，它說做好了，他看到的是更多問題，或同一種輸出。然後是「這沒發生，請修」「我修了」「還是有問題」。這是原型快速修補的老問題。

[50:16](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=3016s) Joe 覺得 Windsurf 有一點不同：它想修問題，而這本身變成問題。Simon 交出的 app 有 ESLint 設定，很多 code 違反它。Windsurf 就循環著說我注意到 lint、我來修，即使不是它引入的。它想尊重環境、保持乾淨，這次卻把 Windsurf 搞糊塗了。他們把那個設定整個拿掉，它才不再守一個原本就沒達到的品質門檻。Macey 覺得兩次 Joe 都抽到較短的籤。Simon 在 Base44 裡幾乎立刻有能動的原型，幾乎沒除錯，code 在不在看過，但完全沒讀，因為不需要。Joe 要的幾乎是同一件事，立刻進了迴圈。

[51:30](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=3090s) Simon 說自己最初的 prompt 很短。他開始寫 SimCity 的點子，打到 prompt 時改成五個字，而且就是 Macey 在正式題目上寫的那五個字。等很久，他有點擔心。他覺得 Base44，以及他用 Bolt 的經驗，都比用完全相同的 prompt 去叫 Bolt 做要花更久。回來之後，作為原型它能動，點一點沒有太多問題。他大概用了五次 prompt 或更少。Macey 的題很短，他幾乎在給 Base44 的第一句就碰到了。若整個團隊都用 Base44，問題是它開始加自己的持久層。事後他會在一開始就說不要加你自己的認證、不要用你自己的持久模型。聽眾聽不到的部分是，他得離線改成本地持久，他們才能繼續。Joe 說 Base44 一開始就有一批鎖死。這類工具在你對功能沒有很強意見時很好用。你要某種小鎮模擬，但沒有規定有哪些功能，它會幫你把範圍想開。若你帶著很強的想法，要它長得怎樣、怎麼運作，就是另一件事。Joe 自己的狀態管理他沒弄動，他記得大概只在記憶體裡，重新整理就沒了，因為它當時沒在動，所以也不確定。Simon 意外 Bolt 沒有提議用 Supabase。他向不熟 Bolt 的人解釋，Supabase、Netlify 和其他低摩擦的路都有。那也是一種鎖，只是和 Base44 不同。他意外它沒有問要不要用 Supabase 當持久層。他意外 Base44 能多快做出原型，也意外在 Joe 的環境上用 Cursor 再往前走會碰到這麼多問題。他沒能把 Joe 的應用再推進去。Joe 說那是因為不是他手寫的。

[54:42](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=3282s) 他們事先以為兩人都會先請 Cursor 或 Windsurf 概述這份 code 是什麼、怎麼運作。兩人都沒有。過程一樣：把東西跑起來，不看比需要更多的東西，然後直接改。Joe 這邊稍微被絆住。若程式庫的品質你不在乎，你只是來加快改、加功能，不是來維護一座漂亮的 code 花園，何必理解它。LLM 能改，瀏覽器裡看起來能動，對這個練習就夠。Simon 說自己是為了趕時間。他和 Dion 談的時候還想先問「跟我講這個」，坐下來就覺得不必，他知道自己要做什麼。真實世界在時間壓力下可能也會這樣。他喜歡 Joe 一開始就描述應用在做什麼。想知道有沒有這段描述，結果會不會不同。Joe 的理由是：它看得到 code，看不到介面。他想給它一點眼睛和意圖。code 都在，重點是什麼、它在驅動什麼。他沒有資料證明這有沒有幫助，只是直覺上他在跟一個對一整面是瞎的東西合作。

[56:59](https://www.youtube.com/watch?v=dzXGY8YUx-8&t=3419s) Macey 問 Simon 能不能猜出 Joe 在原型末期做了一件和功能無關、打算讓他迷路的事。Simon 猜不到。Joe 的第一個念頭是叫它把 code 變得人盡量讀不懂，像編譯後的東西。程式當時還不能動，這樣太不公平。於是改成把函式和變數名換成好笑、會誤導的名字。時間快到了，它做得不好。LLM 也許不擅長解釋「好笑」。Simon 說這有點危險，因為那些名字會變成 context，可能把模型自己搞糊塗。他以為 Joe 會把鎮命名成 Beijing Stoke，完全沒注意到。他自己也曾開玩笑說要把 code 混淆掉。兩人除了 Joe 碰上麻煩時，其實都沒怎麼看 code。他不知道嚴重混淆的 code 會不會讓 LLM 迷路，還是它仍能看懂。Joe 說其中一個選擇是把 `initial state` 改名成 `initial chaos`。Simon 看到了，還想過要不要提，覺得一提會顯得很蠢，但心裡確實想過為什麼會有 chaos。不是最好笑的轉折。Joe 想再推遠一點，也許該叫它全部改成法文。他們希望收在一小時裡，結果加上錄音外的調整，超過三小時。這集和他們平常的形式不同，四個工具裡也許能讓人認識一兩個新的。

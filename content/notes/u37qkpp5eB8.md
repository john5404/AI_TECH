# Inside Kikimora: We Built a Dark Software Factory

片長 15 分 51 秒，英文手寫字幕。講的是 Tessl 的 Dark Factory，名字是 Kikimora。中間有幾段沒被摘到。預告片裡的「九成」在這支片裡說成遠超過 90% 的工作交給雲端。

- 原片：[YouTube](https://www.youtube.com/watch?v=u37qkpp5eB8)

## 一句話

Dark factory 是更自主地做軟體，事實上是不再監督軟體怎麼被做出來。說話的人一開始覺得做不到。他們故意快跑去撞牆，並說這是有疣的 alpha，你可以用。說服人這很安全很難。寫 code 的能力不再有用，agents 大概做得比你好。遠超過 90% 的工作交給雲端，剩下大約 10% 是他想多花時間打磨的前端。大約每一兩週比前一週快 30%。

## 不再監督軟體怎麼被做出來

[0:00](https://www.youtube.com/watch?v=u37qkpp5eB8&t=0s) 一開始他覺得做不到。他們故意快跑、直直撞上很多牆。但他們說沒關係，這會是有疣、全部攤開的 alpha，你可以用。說服人這很安全很難。那句話結尾有一個很大的、存在性的問號加驚嘆號。寫 code 的能力其實沒有用。Agents 大概做得比你好。他說手指交叉，希望兩年後大家還有工作。

[0:47](https://www.youtube.com/watch?v=u37qkpp5eB8&t=47s) 他在 agent enablement 團隊，特別做 Dark Factory，他相信這就是今天要講的。Dark factory 是用更自主的方式做軟體。事實上非常自主：我們不再監督軟體。

[3:34](https://www.youtube.com/watch?v=u37qkpp5eB8&t=214s) 他們得停止一條一條前線地打。要問的是：有沒有一個根本不同的模型，至少把解法烤進問題裡。

[4:17](https://www.youtube.com/watch?v=u37qkpp5eB8&t=257s) Night Shift 是他為副作用自己做的內部 orchestrator。目標是完全不看 code。

[5:18](https://www.youtube.com/watch?v=u37qkpp5eB8&t=318s) 一開始他們把這看成「糟了」。中間有一段沒被摘到。

[7:19](https://www.youtube.com/watch?v=u37qkpp5eB8&t=439s) 有一聲歡迎來到 AI Native Dev London 2026。有人在團隊另一個人正透過 dark factory 做很重要的事時，把他的筆電蓋上。

[8:21](https://www.youtube.com/watch?v=u37qkpp5eB8&t=501s) Rob Willoughby 在第一週就去跟領導層警告，他們 maybe 會落後進度。他記得那種感覺像是伸手太遠。

## 身分是寫 code 的人，現在要被說服

[9:57](https://www.youtube.com/watch?v=u37qkpp5eB8&t=597s) 他們在說服的是在一個學科裡長大的工程師。那個學科說，你寫 code 的能力是最重要的，因為那是你獨特的地方，而且你因此被付得很好。

[10:40](https://www.youtube.com/watch?v=u37qkpp5eB8&t=640s) 遠超過 90% 的工作現在交給雲端。剩下的 10% 大多是他想多花時間打磨的前端變更。他覺得大約每一兩週，會比前一週快大約 30%。

[13:35](https://www.youtube.com/watch?v=u37qkpp5eB8&t=815s) 團隊裡一個設計師過來說：我剛交出第一張 PR，這輩子沒這麼有力量過。現在 GTM 團隊在用 Dark Factory。People 團隊也在用，做的任務跟寫 code 無關。非開發團隊擁抱工廠時，他們也碰到各種缺口和更難的事。他們把這些學到的東西做回產品。

[14:00](https://www.youtube.com/watch?v=u37qkpp5eB8&t=840s) 歷史上，一項技術讓有價值的事變得更多人做得到，並把人從「自己做那件事」轉成「讓別人做得到」，一直是基礎轉變的方式。一旦你開始用 software factory，它替你跑很多 code，而且你看到很多成功，心態會變，你對軟體將怎麼被做出來的想法也會移。

[14:37](https://www.youtube.com/watch?v=u37qkpp5eB8&t=877s) 今年稍早的 AI Engineer，Theo 做閉幕演講。他強調的一點是：我們的企圖不夠大。有很多事可以更快解決。以前要整支工程團隊才能交付的產品，現在一個很強、有產品頭腦的人就能交付。有些很厲害的人類問題，可以比以前快很多交付。

[15:07](https://www.youtube.com/watch?v=u37qkpp5eB8&t=907s) 對他來說這就是新的 software engineering。當其中一個在做、並弄清那些細節的人，非常刺激。選兩個？不，這次是三個都要。實作工作不可避免會由這個來做。幫這個過程，並把你的思考改成更大的東西。
